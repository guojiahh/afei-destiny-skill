# 个性化人生海图演示

这是可重建的本地设计演示，尚未接入正式咨询报告生成。人物、对话、经历、反馈和路线全部虚构，没有排盘，也不读取真实咨询目录。

## 预览与重建

从仓库根目录运行：

```text
python3 design-demos/report-v5/build.py
```

生成[第五版独立 HTML](../visual-report-v5.html)。它内嵌数据、样式、脚本和帆船图片，可以单文件打开。页首可切换虚构人物，主图、点击解读、图文报告和图片导出使用同一份案例数据。

- [cases.json](cases.json)：各案例的阶段、选择和图文解读。
- [atlas.js](atlas.js)：根据节点数量排布航线，处理播放、切换和导出。
- [details.js](details.js)与[details.css](details.css)：图文解读。
- [template.html](template.html)：继承第四版的主图与阅读外框。
- [build.py](build.py)：校验数据并生成单文件产物。

## 什么固定，什么因人而异

固定的是纸色、海面、帆船、实线与虚线的含义，以及图表的阅读方式。每份内容决定自己的阶段数量、节点名称、当前处境、未来分支、成立条件、解读主题、行动节奏与反馈记录。布局从数据计算，不随机生成差异，也不为了饱满补齐节点。

页首的多人物选择器只用于比较虚构演示。正式交付应每份文件仅包含当前用户、当前咨询的数据。

每个 profile 包含 `history` 数组、一个 `current` 节点、`choices` 数组和 `detail` 图文内容。节点使用稳定的 `id`，含短标签 `label`、点击标题 `title`、说明 `body`、来源 `source`、核验状态 `status`。`age` 允许缺省或为空，界面会显示“时间未定位”；这不改变叙述顺序。每条未来分支必须含 `condition`。

节点数量直接来自 `history.length + 1 + choices.length`。手机节点增多时增加纵向图高，保留可读字号。点击或键盘选择后只展开该节点的解读。切换人物时取消旧动画，重置当前节点，同时替换图文内容；图片导出捕获开始保存时的案例快照。

## 正式接入仍需处理的边界

- 只能从当前咨询的已登记报告和反馈提取阶段；不得跨会话拼接。
- 用户叙述、分析推断、已确认反馈与未核验假设需要分别登记来源。演示中的 `source` 是虚构来源标签，正式接入需换成可回查的引用。
- 缺少经历或时间时保持未知，不补齐年龄、年份或转折。
- 未来路线是有条件的备选项，不表示必然事件。没有明确选择时允许不画未来分支。
- 曲线高度、节点间距与海岸位置只用于排布，不表示吉凶、时长、成功率或人生评分。
- 图文中的状态来自对话反馈，不把确认数量换算成预测准确率。
- 仍须遵守正式报告来源与校验协议；本演示没有替代现有 Markdown 报告交付。
