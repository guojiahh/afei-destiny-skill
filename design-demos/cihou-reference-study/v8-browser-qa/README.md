# V8 实际浏览器 QA

本目录记录 2026-10-17 的真实浏览器检查。仅使用 CUA 控制 Codex In-app Browser；新建两个自己的后台标签页，未操作用户原有页面。QA 只保存截图、动作记录与本说明，没有修改实现代码，也没有审美评分。

## 最终结果

最终人物回望与道路横截面修正后，fresh 390×844 完整序列和 1440×900 主图序列均通过本轮检查。所有 hero 关键帧的 scrollY 为 0；390 的 clientWidth、scrollWidth、innerWidth 均为 390。1280×720 还完成了前一轮分段长按、阅读与重播检查。

- 实际看到：开场居中的行走角色；按住后花与人物特写；松手后镜头停留且角色表演继续；续按累计展开完整环；原生点击“再往前一步”后，手边金色形状、落点附近的小叶、铺开的新路、最终橙花与叶片；回望朝身后；结束时阅读与重播入口出现。
- 实际操作通过：390 以 2.0 + 3.0 + 5.5 秒三次原生长按完成全环，随后出发、阅读、回到画面、重播、再次长按。1280 同样完成三段累计长按。1440 最终轮用一次 10.6 秒长按复验环与修正后的出发道路。
- 最终截图未见旧路近侧的折线尖齿；人物独立预览下沉、回望与三个行走相位未见膝断节、明显悬脚或头颈分离。角色 agent 已复审这些真图。

## 已发现并复验的问题

1. 早期回望静帧中脸仍朝前。角色 agent 根据 [旧回望真图](actor-glance.jpg) 修正，最终回望图已看到单一头像朝身后、颈与衣领相接。
2. 早期新路近侧有折线、自交尖齿。[旧路真图](1440-04-road.jpg) 保留；场景 agent 修正横截面与弯势后，390 与 1440 的最终截图不再出现该缺口。
3. locator.click 对底部 CTA 触发驱动自动居中，造成 scrollY≈280.5、主图顶部裁切。[受影响的截图](wide-06-depart-seed.jpg) 保留作驱动行为证据，不作为页面缺陷。改用原生坐标点击后所有 hero 采样 scrollY=0；root 也独立复现该驱动差异。
4. 直接把已完成并长时间继续行走的宽屏场景 resize 到 390，曾看不到花；fresh 390 全序列的结束帧清楚看见橙花。前者只记录为不同时间状态，未据此判定 fresh 手机流程缺失。

## 操作与证据边界

- 实宽来自页面可见 DOM 的 innerWidth / innerHeight / devicePixelRatio 只读查询，不从截图显示大小推测。初轮 1280×720 dpr2；最终 1440×900 和 390×844 为 dpr1。
- viewport 能力在本轮实际只作用最近创建的标签页。初次 set 到 1440 时旧主图页仍是 1280，已分别记录；没有把旧页截图冒称为 1440。
- 原生长按通过 CUA click 的 durationMs；出发关键帧按点击后的预定取样时间抓取。截图与调度有小幅延迟，精确动作记录见 [actions.json](actions.json)。
- 预览页 slider 的键盘 seek 会切换到 sequence；最终 walk 三帧均重新点击“行走”后在实际动画中暂停取得，未用 seek 帧冒充 walk。
- 本报告没有读取代码来判定动画视觉。时间轴建议来自场景 agent，仅用于选择采样点；金色形状、叶、花、道路和回望的结论来自所列截图。未测试真实触屏硬件、其他浏览器、屏幕阅读器或低性能设备；没有由本轮结果推断这些平台的表现。
- 宽屏旧轮文件以 wide- 或 1440-0 开头；最终道路证据以 1440-final- 开头，手机最终轮为 390-01 至 390-12。所有旧证据保留。
