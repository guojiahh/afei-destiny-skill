# 闭环叙事：此刻、来处与可能

本协议用于 `cihou-mobius-v1` 的个人主图内容。生成和登记仍按 [HTML 报告协议](html-report.md)；循环、事实、解释与行动来自本次已登记的双底稿，不由路的形状、行走圈数或命盘自动推断。

固定的是帮助读者理解自己的结构：**当时发生什么 → 怎样理解 → 怎样应对 → 眼前有什么作用 → 后来有什么代价 → 什么又促使同一做法发生。** 每一份报告重新写这个人的答案；不能将固定结构变成固定人生故事。

## 先确定能否形成这条联系

先还原最近一次具体经过，而非从“拖延”“不表达”等标签开始。需要了解目标、触发、想法与感受、实际做法、即时变化和后续结果。最关键的核对是：这个做法当时帮到了什么，后来发生的事是否又促使它被使用。

当前做法可能有实际价值，也可能伴随长期代价。不要为了制造“原来如此”而把合理准备、必要等待、制度限制、资格门槛、收入压力或照料责任写成个人心理问题。两种原因可以同时存在。

可以根据当前情境、应对方式和它的即时作用，提出一个有机制依据的解释；在需要表达推演的那一处，用自然的“你可能……”说明范围。若关键联系没有支持，保留开放表达或省略因果，不靠环的形状补齐。事实状态与推演起点保存到来源底稿、模型和技术依据，正文无需逐句重复方法声明。

## 模型合同

`presentation.hero_runtime="wayfinder-v19"` 使用 `presentation.loop_story`。它与三个 `hero_states`、可选三个 `hero_choices`、九章正文及来源绑定共同组成同一份个人模型。

```text
loop_story
  nodes: 恰好六项，固定顺序如下
    trigger → meaning → response → relief → cost → return
    每项: {id, text, detail, refs}
  past: {text, refs}        可选
  present: {text, refs}     必填
  future: {text, refs}      必填
```

| 字段 | 职责与长度 |
|---|---|
| `nodes[].id` | 固定六个 ID，不增删、重排或复用 |
| `nodes[].text` | 画面中的一句短话，非空，最多24字；尽量只说一个意思 |
| `nodes[].detail` | 按需解释这一环、成立条件和核对点，非空，最多300字 |
| `nodes[].refs` | 本次双底稿的有效章节引用，非空；不能以“图上有这个位置”替代材料 |
| `past.text` | 已谈过的历史联系，或由当前机制推演的可能形成路径；可省略，最多600字 |
| `present.text` | 当前处境、目标、机制假设与主要限制，非空，最多600字 |
| `future.text` | 一个条件式实验与必要支持、观察和调整方式，非空，最多600字 |
| `past/present/future.refs` | 本次有效章节引用，非空；指向实际叙述或明确标注为解释推演的来源段落 |

`refs` 的格式与有效性沿用 HTML 协议。引用说明材料位置，不表示已经证明因果。涉及个人想法或历史的句子，必须能在用户底稿中区分本人叙述、解释假设和未知；传统技术解释不得补作个人经历的证据。

### 六个位置每次怎样写

| ID | 先核对什么 | 可填写的抽象句式 |
|---|---|---|
| `trigger` | 哪次具体情境开始卡住 | 当【本人描述的情境】靠近 |
| `meaning` | 当时怎样理解，担心什么 | 我想到【本人描述的含义】；未知就保留待核对 |
| `response` | 实际做了什么 | 我会【具体行为】 |
| `relief` | 行为之后，当时发生什么变化 | 这样一来，【本人确认的即时作用】 |
| `cost` | 后来观察到什么结果或代价 | 过一段时间，【具体后果】 |
| `return` | 后果是否促使原做法重复 | 【后果】是否又让我更容易【原做法】 |

句式是写作槽位，不是直接交付文案。先辨认行为在眼下起什么作用，再自然解释它如何带来后续影响。未被提供的想法和即时感受可以作为机制解释提出，在相应句子用一次“可能”说明，不自动升级为本人原话；也不在每个节点反复加上“假设／没有材料／待核对”。实际资格、资源和他人行为造成的限制，仍应在相关行动旁说具体。

## 读者的三个视角

三态按 **此刻／来处／可能** 排列。模型的 `diagram.tour` 对应当前机制、经历与行动节点；最后一态仍必须指向 `action`，不能让动画决定外部回应。

1. **此刻：先体验，再看见。** 首屏按住沿固定路线向前，松开停下，依次遇见六个位置；一圈后仍回到第一项，可以继续观察。完成一圈不自动进入来处，不按圈数解锁人生结论。六句都来自本次 `loop_story.nodes`。
2. **来处：理解一种办法怎样学来。** 区分“怎样形成”与“今天怎样持续”。可以连接已讲过的经历，也可以从当前应对的作用，提出“你可能曾经……”的形成路径，例如某种做法曾更容易带来认可、秩序、安心或避免冲突，后来成为熟悉的规则。推演停留在广义的学习经验，不具体化为某位家人、某个年龄、某次考试、创伤或诊断。读者已提供的例外和支持也可以进入来处；不需要把每个人的过去都写成损伤，也无需一律停在“过去未知”。
3. **可能：比较条件，选择小步。** 不同走法说明条件、成本与支持，彼此不排价值高低。选择先预览含义，主动尝试才表示视觉上的一步；改变景色、走出路线和动画结束都不表示现实成功。

读者可直接切换视角、阅读正文或停止观看。不能把必须走完动画当作阅读、纠正或作选择的门槛。减少动态与无脚本阅读保留同一组文字含义；暂停或浏览器选择不写入咨询状态。

## 自然叙述与来源分层

写给读者的文本采用直接、温和的第二人称，先让人读懂“这个办法为什么会被反复使用”，再看见能改动的环节。主图、诗句、六节点说明和正文不要轮番重复“这是一个假设”“没有依据”“仍需核对”等方法用语。将一处必要的解释层级说明放到可展开的依据中，适用条件放在真正影响行动的位置。

可能的过去可以这样组织：**“你可能曾经发现【这种做法更容易带来什么】，而【另一种做法带来什么代价】。久而久之，【规则】成了熟悉的办法。到了眼前的处境，【环境变化】让它原来的用处与今天的代价交织在一起。”** 可能语气限定整条形成路径，不必每句再加一次。

来源层继续区分叙述事实与解释推演。个人底稿在提出路径的段落自然使用“你可能”，模型节点或作者元数据记录 `kind=hypothesis` 与推演依据；技术依据和来源计划保留它不是已核实传记的身份。引用这一段支持的是“已经提出的解释”，不能用同一句解释反过来证明过去确实发生。不得将推演具体化为未经提供的父母言行、年龄、地点、事件、诊断或遭遇。

这套写法适用于工作、学习、关系表达、照料和其他实际困局。每次替换的是行为的功能、当下环境和具体选择，不把求职中的“准备换安心”套给所有读者。

## 每份报告的固定写作顺序

先在双底稿中写清下列八项，再把短句压缩到主图，不反过来用动画补内容。

| 位置 | 本次要写的内容 | 无材料时 |
|---|---|---|
| 当前处境与愿望 | 想靠近什么，为什么重要，现实限制 | 保留目标或条件未知 |
| 触发时刻 | 最近一次具体经过 | 先请求具体经过，或明确条件式例子 |
| 应对与即时作用 | 做了什么，当时有何变化 | 不默认存在安心或保护 |
| 循环与后续代价 | 后果如何回到原应对，最强反例 | 回连待核对，不写成结论 |
| 可能的历史联系 | 已讲过的往事，或当前机制支持的可能形成路径 | 用一次“你可能曾经……”表达广义路径，或省略；不补造具体事件 |
| 例外、能力与支持 | 已发生的不同做法和可用条件 | 不自动生成优势与资源 |
| 一个可尝试的改变 | 适用前提、最小步、完成线、观察点 | 继续了解、争取支持或暂缓也可 |
| 邀请核对 | 哪句准确，哪句需要改写 | 保留具体纠正入口与原对话说明 |

未来部分至少说清：什么前提下值得试、由本人控制的是哪一步、做到哪里算本轮完成、观察什么、何时缩小或暂停，以及什么结果不由这一步保证。未来窗口若包含传统解释，继续与现实实验分别说明；不把年份写成尝试必然奏效的原因。

“觉得很准”不能取代核对。本人不认同，就回到材料修改解释；尝试没有发生，也要重新检查目标、步子和支持，不据此责怪读者抗拒改变。

## 极短的求职示意

以下仅是假设性写法，不属于任何咨询者，也不是通用默认文案。前提必须另有材料：本人确实想申请、基本材料已完成、临近投递担心被拒绝，且推迟后会暂时轻松。

```text
想到投递和被评价
→ 如果被拒，是不是我不够好
→ 再改一轮，今天先不投
→ 暂时安心，还不用面对结果
→ 投递推迟，真实反馈更少
→ 没有把握，又想继续准备
```

来处可以写：“你可能曾经发现，准备充分更容易得到认可，太早开始则容易被挑出问题。久而久之，先做好一点成了让自己安心的办法。”这是从当前准备—安心的作用提出的可能路径，不添加具体人物和事件。若关键要求已满足，可以为必要检查约定结束时间，尝试投一份，再观察最难的环节；若资格或材料确有缺口，就先做有限准备；若精力或方向不足，就先核对支持与意愿。三种走法都不保证回复或录用。

如果本人说推迟没有带来轻松、资格尚未满足，或已经投过很多次，应相应修改这张图。不能把这段示意直接换成另一个人的名字。
