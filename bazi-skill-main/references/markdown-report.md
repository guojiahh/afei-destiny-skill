# 完整 Markdown 咨询报告

本文件规定引导式咨询收束后的面向用户交付。目标是把命盘事实、开场盲测、用户反馈、全部可分析主题、重点问题、未来展望和现实建议整理成一份详细、温暖、可追溯的 `final_report.md`。它不是聊天记录拼接，也不是 HTML 模板；详细技术推导另写入 `technical_analysis.md`。

## 一、生成条件

用户同意生成报告，或一开始已经明确要求完整报告后：

1. 运行 Harness `audit`；失败则停止；
2. 进入 `report_ready`；
3. 用输出路由器生成 `report_source` 计划；
4. 只读取计划列出的活动产物；
5. 写入 `consultation_state/final_report.md`；
6. 将文件登记为 `markdown_report`，来源指向参与报告的活动产物；
7. 按 `technical-report.md` 生成并登记独立的 `technical_analysis.md`。

用户要求立即报告时，不因缺少盲测或深入对话而阻止交付；把缺失部分标记为“未进行”“未深入”或“未经反馈校准”。

## 二、来源与标签

报告中的主要内容在写作时区分四类来源，不必每句话都加标签，但章节和关键结论必须看得出来：

- **命盘原判断**：形成于读取用户经历之前；
- **用户已确认**：用户明确反馈为准或提供了可核对事实；
- **反馈后修正**：根据用户反馈调整了领域、形态、时间或置信度；
- **尚未核验**：基于命盘形成，但未经过用户现实反馈。

不得把用户讲述的经历改写成“命盘早已预测到”。不得隐藏不准的盲测，也不得把已知事实计作命中。

## 三、固定报告结构

### 封面信息

- 报告标题；
- 用户称呼或匿名编号；
- 出生信息与采用口径；
- 生成日期；
- 一句传统文化解释边界。

### 一、本次咨询总纲

先用人话写一段有分量的总体理解：用户的主要资源、当前矛盾、最值得把握的方向。先让用户感到被理解，再进入术语。不要用空泛赞美。

随后列出：

- 本次最稳定的 3–5 条结论；
- 当前最重要的现实问题；
- 一项最大不确定来源；
- 一段“你可以怎样使用这份报告”。

紧接着提供“重点阅读导航”：明确用户入口选择和对话中最终聚焦的主题位于第几节，建议先读哪三节。关注主题只改变篇幅和导航，不删掉其他可分析主题。

### 二、命盘与计算口径

- 四柱表、十神、藏干；
- 公历/农历、换年、换月、换日、真太阳时与起运口径；
- 边界时刻、未知时辰和可能影响；
- 大运列表与当前阶段。

不要粘贴原始计算器 JSON。

### 三、命局结构完整分析

读取 `structure-analysis.md` 和 `relations-and-transformations.md`，分别说明：

1. 日主、月令与季节环境；
2. 根气、透藏、生扶、耗泄与制化；
3. 旺衰判断及最强反例；
4. 常规格局或特殊格局门禁；
5. 格局、扶抑、调候、病药和通关的不同语义；
6. 关键合冲刑害、是否真正改变结构；
7. 结构优势、现实成本和适配环境。

术语第一次出现时立刻翻译成人话。

### 四、开场盲测与真实反馈

按原顺序完整保留：

| 编号 | 锁定判断摘要 | 用户反馈 | 保留部分 | 放下或修正部分 |
|---|---|---|---|---|

表格后写一段诚实结算：哪些方向得到支持，哪些只部分吻合，哪些没有说中，哪些无法确认。不要计算或展示科学准确率。

### 五、用户画像与运行方式

综合命盘原判断和用户反馈，写用户在现实中可能表现出的：

- 接受责任与处理压力的方式；
- 学习、表达、创作或解决问题的方式；
- 与规则、评价和外部反馈的关系；
- 资源选择、长期投入与边界；
- 关系中的承载、期待和退出条件。

只写本次证据支持的部分。用户未讨论的领域标为尚未核验，不假装已经了解。

### 六、重点主题深度分析

这是报告篇幅和心理价值的核心。按以下顺序展开：

1. 用户真正提出的问题，不替他改写成另一个问题；
2. 用户在对话中表达的现实处境；
3. 最主要的内在拉扯或决策难点；
4. 命盘机制怎样提供一种理解框架；
5. 用户反馈怎样支持、削弱或修正该解释；
6. 有利条件、风险条件和最强反例；
7. 可执行的现实路径。

先承接用户的投入、困难和愿望，再分析。不要用命理术语压过用户真实问题。

### 七、人生主题全景

将目前能够分析的主题全部过一遍，并用清晰的小节导航：

1. 自我认识与行为节奏；
2. 学习、考试与能力形成；
3. 事业、职责与发展方式；
4. 财务、资源与现金流；
5. 感情、亲密关系与边界；
6. 家庭角色与代际互动；
7. 迁移、居住与环境变化；
8. 身心节奏与安全提醒。

每个领域包含：目前能支持的判断、现实表现、适配环境、常见代价、反例、置信度和可观察点。用户选择的重点主题放在第六节详细展开，在本节只给交叉索引；其他领域即使未深入也要说明“能分析到哪里、还缺什么”，不能用模板凑长度，也不能直接省略。

健康只谈作息、压力管理和就医提醒，不做诊断；财务不承诺收益；关系不替当事人做重大决定。

### 八、未来阶段与时间窗口

无论用户是否主动问未来，完整报告都包含本节。具体规则见下一节。

### 九、行动建议

建议分为：

- 现在就能做的；
- 未来三个月可验证的；
- 进入重要窗口前应准备的；
- 不建议仅凭命理决定的事项。

建议必须脱离命理也能独立成立，并与前文问题对应。

### 十、结论边界与未解问题

列出：

- 高、中、低置信度内容；
- 没有说中的盲测；
- 未知时辰、边界口径或流派差异；
- 尚未核验的人生领域；
- 若要继续咨询，最值得补充的一项信息。

### 附录：阅读索引与技术文档说明

列出重点主题、相关章节、未来窗口和仍待观察的问题。详细的盘面事实、结构竞争、传统规则、岁运触发链、候选筛选和反证统一放在同目录的 `technical_analysis.md`，不在用户报告里重复堆术语。

## 四、未来展望

即使用户没有在对话中主动询问未来，也根据活动命盘、大运和当前年份形成一节“未来阶段展望”。该节必须标记为：

> 以下内容基于当前命盘与岁运结构，未经过未来现实反馈校准，用于观察和准备，不是确定事件承诺。

按阶段而非神谕写作：

| 时间窗口 | 背景主题 | 更容易出现的机会 | 需要留意的条件 | 可以提前做什么 |
|---|---|---|---|---|

表达顺序采用“可利用资源 → 可能机会 → 风险条件 → 主动准备”。未来尽量写得让用户有希望和行动感，但不得：

- 为了好听承诺升职、发财、结婚或成功；
- 把风险全部删除；
- 用灾祸、寿夭、疾病制造恐惧；
- 把超过证据粒度的具体事件包装成必然。

风险使用条件式语言，例如：“如果责任扩张快于资源补充，压力会先出现；提前谈清边界，可以把这一阶段更多转化为能力和位置的积累。”

## 五、语言与心理承接

完整执行 `client-voice.md`。报告应让用户获得理解、认同、启发与现实主动权：

- 先看见用户已经承担的成本，再谈需要改变的部分；
- 先指出可用资源和长处，再说明长处失去边界时的代价；
- 把“你不行”改为“当前机制在什么环境下难以发挥”；
- 把“命中注定”改为“你能提前识别和选择的条件”；
- 把建议写成用户可以尝试的路径，而非命令。

认可用户的感受和投入，不必认可用户对自己或他人的每个结论。温暖不能删除事实、反例、失误和现实风险。

## 六、详细度标准

完整引导式报告默认是长报告。证据充分时，以 4,000–8,000 个中文字符作为常见范围；复杂主问题可以更长。不要为满足长度重复同义句或制造细节。

重点章节至少完成：

1. 结论；
2. 命盘或对话证据；
3. 现实翻译；
4. 成立条件和反例；
5. 对用户意味着什么；
6. 可执行建议。

若资料不足，宁可明确写“本次未深入”，不要用通用性格话术填满页面。

## 七、生成与登记

生成来源计划：

```powershell
python scripts/consultation_output_router.py `
  --session-dir consultation_state `
  --intent report_source `
  --output report_source_plan.json `
  --register
```

依据计划写入：

```text
consultation_state/final_report.md
```

随后登记为 `markdown_report`，并把所有实际使用的活动产物 ID 作为来源。报告文件不得写入 Skill 目录，不得包含 Benchmark，不能读取 `stale` 或 `superseded` 产物。

```powershell
python scripts/consultation_harness.py register `
  --session-dir consultation_state `
  --kind markdown_report `
  --path consultation_state/final_report.md `
  --source-category prior_output `
  --source-artifact <实际使用的活动产物ID>
```

重复 `--source-artifact` 传入全部实际来源。若已有活动 `markdown_report`，先按 `output` 范围 `supersede`，不得静默覆盖。

按 `technical-report.md` 另行生成 `consultation_state/technical_analysis.md`。HTML 尚未实现。未来获得模板后，只渲染这两份已登记 Markdown 及其结构化来源，不重新进行命理推理。

## 八、交付检查

- [ ] 报告来自 `report_source` 列出的活动产物；
- [ ] 四条盲测及全部反馈都在，不只挑命中项；
- [ ] 主问题得到详细回应，而不是被通用命盘分析淹没；
- [ ] 八个可分析主题均有章节，重点阅读位置清楚；
- [ ] 用户原话没有被包装成命盘独立预测；
- [ ] 未来展望存在，并标明未经未来反馈校准；
- [ ] 未来先写机会和准备，再写条件风险，但没有虚假承诺；
- [ ] 全文说人话，术语有解释；
- [ ] 用户得到理解、启发和行动感，同时反例和边界仍完整；
- [ ] 输出为 `final_report.md`，HTML 未被临时拼接；
- [ ] 报告已登记为 `markdown_report` 并保留来源血缘。
- [ ] 独立 `technical_analysis.md` 已按 `technical-report.md` 生成，且与用户报告一致。
