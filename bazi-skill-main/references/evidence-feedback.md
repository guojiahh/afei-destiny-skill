# 证据隔离、回溯核验与反馈修正

本文件规定用户经历怎样进入咨询。目标是让分析能一步步校准，同时防止冷读、迎合和事后改写。

## 一、四种操作必须分开

1. **收集事实**：保存用户主动提供的出生信息、问题和经历。
2. **读取事实**：当前阶段是否允许查看这些信息。
3. **盘面推断**：只用排盘事实和当前允许的传统规则形成结论。
4. **咨询映射**：结论锁定后，用用户背景调整解释、问题优先级和现实建议。

“可以读取”不等于“可以当作盘面证据”。用户说过的经历、性格、关系状态和结果，不能被重新包装成模型独立推断出的内容。

## 二、操作性输入与传记信息

以下属于排盘或任务所需的操作性输入：

- 出生日期、时间、地点、历法类型；
- 时区、夏令时、真太阳时与换日口径；
- 传统大运顺逆所需的性别口径；
- 用户当前具体问题和时间范围。

以下属于用户传记信息：

- 已发生的工作、学业、关系、家庭、健康、迁移和财务事件；
- 用户对自己性格、能力和人生阶段的描述；
- 对上一轮判断的命中、部分命中或不命中反馈。

传记信息默认不参与首次盘面结论，只在回溯核验、出生时间校准或结论锁定后的咨询映射中按规则使用。

## 三、首次分析的盘面锁

读取用户传记信息前，先形成一张“盘面锁”：

```
问题：
排盘口径与不确定项：
核心结构判断：
支持事实（2-4条）：
最强反证：
允许的事件粒度：
过去窗口候选（2-3个）：
未来窗口候选（最终报告默认形成；未讨论时标记为未校准）：
初始置信度：高 / 中 / 低
```

锁定后不得静默改写。出生时间、日期口径或计算事实发生变化时可以重算，但要说明“输入改变”；仅因用户说“不像”而换一个故事，属于无效修正。

## 四、回溯问题怎样设计

回溯用于区分结构假设和检查时间分辨率，不用于诱导用户提供可套用的故事。

### 合格问题

- 时间有限：给一年或两年窗口，不给十年宽区间。
- 领域有限：每题最多一到两个类别。
- 方向可辨：区分建立/扩张与中断/收缩，而不是“有变化吗”。
- 结果可选：用户可以回答命中、部分命中、不命中、不确定。
- 有信息增益：不同回答能够改变结构候选、时间精度或后续问题。

示例：

> 2018–2019 年是否出现过一次职责明显扩大，同时伴随团队、岗位或居住安排变化？如果只有其中一项，请分开说明。

不合格问题：

- “你小时候是不是比较敏感？”
- “这几年是不是既有机会也有压力？”
- 一次列出工作、感情、家庭、健康四个领域，任何命中都算准。

## 五、反馈标签

每条原判断保留原文，并用固定标签记录：

| 标签 | 定义 | 如何使用 |
|---|---|---|
| 真命中 | 时间和主要事件类别都吻合 | 可提高该结构/时间解释的相对可信度 |
| 部分命中 | 时间或事件类别只吻合一部分 | 只提高命中的那一轴，不整条算对 |
| 宽泛命中 | 只有普遍主题相符 | 不作为强证据 |
| 不命中 | 时间和主要类别均不符 | 下调候选或检查口径，不强行解释 |
| 不确定 | 用户无法确认或记忆模糊 | 不计分，不当作否定 |
| 已知事实核对 | 事件在推断前已经给出 | 只能用于适配，不能记为预测命中 |

同时分开三轴：

- **领域轴**：工作、关系、家庭、迁移等是否识别正确；
- **事件形态轴**：建立、扩张、重组、中断、终止是否识别正确；
- **时间轴**：大运背景、年份窗口或更细时间是否识别正确。

## 六、修正优先级

用户反馈不吻合时按顺序检查：

1. 出生日期、历法、闰月、时区和夏令时；
2. 晚子换日、真太阳时、时辰/节气边界；
3. 大运顺逆和起运口径；
4. 未知时辰是否让关键宫位或时柱结论失效；
5. 结构候选是否选错，尤其普通格与从/化候选；
6. 事件阶段是否越级；
7. 原问题是否超出八字可识别粒度。

只有 1–4 项发生变化时才重算排盘。第 5–7 项属于解释复盘：必须保留原判断，并标明“反馈后修正解释”。

## 七、反馈能改变什么

可以改变：

- 后续优先分析的领域；
- 两个已存在结构候选的相对置信度；
- 出生时间校准候选；
- 时间窗口的分辨率和措辞；
- 用户能理解的表达、伦理检查和现实建议。

不能改变：

- 已经由计算器确认的四柱或岁运事实，除非输入口径改变；
- 为了匹配经历而新增一条原盘没有的关系；
- 把用户经历写成“盘里早已明确显示”；
- 事后把宽泛主题升级成精确命中；
- 删除不命中项或重算原分数。

## 八、持续对话状态

真实咨询按 `consultation-harness.md` 使用文件化状态，不把完整私人经历写入可安装 Skill：

```
consultation_state/
  chart_facts.json         排盘器输出或其摘要
  chart_lock.md            首次盘面锁
  blind_candidates.json    仅用盘面生成的盲测候选
  blind_probe_manifest.json 已筛选并哈希锁定的开场陈述
  blind_feedback_result.json 固定标签、完整性标记与后续路由
  feedback_log.md          原判断 + 用户标签 + 修正说明
  consultation_context.md  用户关切和表达注意事项
  report_sections/         最终报告所需章节
  session_state.json       阶段、产物哈希、来源类别、失效状态与操作历史
```

这些文件属于用户工作目录和隐私数据，不进入仓库、示例、Benchmark 或技能包。所有正式产物通过 `consultation_harness.py register` 登记；被替代或依赖旧盘的产物保留记录，但只能处于 `superseded` 或 `stale`，不得进入后续输出。

开场盲测按 `opening-blind-reading.md` 使用 `scripts/blind_opening.py`。脚本输出的分数只控制候选排序和转场，不能显示成准确率；用户自由叙述默认不写入机器结算文件，只在 `feedback_log.md` 保存最小必要摘要。

## 九、最终报告中的溯源

报告中的重要段落分三类：

- **盘面判断**：能够脱离用户传记独立复现；
- **回溯核验**：显示原判断和用户反馈，不改原分；
- **咨询建议**：结合现实背景给出的行动建议，不冒充盘面预测。

同一个段落可以包含三类内容，但必须让读者看得出边界。输出路由按 `output-routing.md` 只选择活动产物；最终 Markdown 按 `markdown-report.md` 生成并登记。HTML 只是未来的呈现层，不授权生成器重新合成新结论。

## 十、交付前反事实检查

针对每个关键盘面结论问：

1. 删除用户全部经历，这个结论还成立吗？
2. 如果用户报告了相反经历，盘面证据会不会被我改写？
3. 能否从排盘事实和已加载规则复现支持链与反证？
4. 当前措辞有没有把“用户确认”误写成“独立预测”？

任一答案不合格，就回到盘面锁重做；不能靠更坚定的语气掩盖证据问题。
