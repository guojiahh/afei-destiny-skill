# 开场盲测选择与结算协议

本文件规定统一入口的 `first_read` 阶段。它把不读取经历的第一层判断变成可锁定、可结算、可失败的开场体验。模型从命盘生成候选；`scripts/blind_opening.py` 只负责资格过滤、跨领域选择、清单锁定和反馈路由。

## 一、进入条件

完成以下事项后进入，并由 `consultation_harness.py` 确认会话处于 `first_read`：

1. 出生信息和计算口径已确认；
2. `calculate_bazi.py` 已运行，或题给四柱已明确采用；
3. 已形成不读取经历的 `chart_lock`；
4. 候选生成不读取用户传记、上一轮反馈或已知人生结果。

用户明确说“跳过盲测”“直接回答问题”“一次讲完”时可以跳过。出生时间未知或处于边界时，只选择对候选时辰稳定的共同结论，并说明精度降低。

## 二、候选池

先从命盘独立生成 8–12 个候选，再交给脚本选择。默认选择四条、最多五条。优先覆盖互不重复的方向：

| `domain` | 允许内容 | 不允许内容 |
|---|---|---|
| `timing_event` | 1–2 年内一个领域的一种事件形态 | 多领域并列、超过两年的模糊变化 |
| `learning_path` | 学习方式、过程起伏、制度适配 | 凭盘断具体学校或学历证书 |
| `work_role` | 承责、协作、岗位扩张或收缩 | 具体公司、收入和职位名称 |
| `relationship_pattern` | 建立、边界、承载与退出方式 | 出轨、性取向、生育能力 |
| `resource_pattern` | 机会、资源保存、选择与责任成本 | 财富数额、投资承诺、破产断言 |
| `family_structure` | 家庭角色、照顾与权责结构 | 父母生死、疾病、道德评价 |
| `mobility` | 离乡、迁移、居住重组 | 无时间边界的“环境有变化” |
| `behavior_pattern` | 有明确触发和反向条件的行为模式 | “敏感、善良、外冷内热”等巴纳姆标签 |

推荐的四条组合是：过去事件 + 工作/学习场景 + 关系模式 + 资源/选择。盘面没有足够强信号时可以换领域或少于四条，不能为了凑数降低门槛。

## 三、资格门禁

每个候选必须：

- 只来自 `chart_only` 材料；
- 核心只押一个方向，不把互不相干的事件捆在一起；
- 包含现实场景或触发条件；
- 包含可观察的结果；
- 至少有一条命盘证据和一条真正能推翻判断的反例；
- 用户可以回答准、部分准、不准或不确定；
- 信号强度至少为 `medium`，具体度至少为 `medium`；
- 基础率风险不能为 `high`；
- 不包含健康诊断、死亡、犯罪、灾祸、不孕、出轨、收入数额等敏感判断；
- 时间候选的起止年份跨度不得超过两年。

一个核心判断可以列 1–3 个同义现实例子，帮助用户理解范围；这些例子必须是同一种事件机制，不能把多个方向塞进一句话后任一命中都算准。

“大多数同龄人很容易点头”的句子不能进入盲测。答不出“用户出现什么现实情况时这条作废”，就标为不可证伪并拒绝。

候选输入示意：

```json
{
  "schema_version": 1,
  "source_scope": "chart_only",
  "chart_lock_id": "session-001-chart-v1",
  "candidates": [
    {
      "id": "probe-work-01",
      "domain": "work_role",
      "claim": "在规则明确且结果需要有人承担时，你更容易主动接管，压力往往晚于责任感出现。",
      "evidence": ["月令与官杀/印比功能链的盘面依据"],
      "counterevidence": ["若现实中长期先拒绝责任，即使边界明确也不承接，则本解释作废"],
      "evidence_strength": "strong",
      "specificity": "high",
      "base_rate_risk": "low",
      "falsifiable": true,
      "biography_independent": true,
      "atomic": true,
      "sensitive": false,
      "time_window": null
    }
  ]
}
```

示例只展示字段，不得套用到具体用户。

## 四、选择与锁定

运行：

```powershell
python scripts/blind_opening.py select `
  --input consultation_state/blind_candidates.json `
  --output consultation_state/blind_probe_manifest.json
```

脚本默认选择四条，允许 `--count 1..5`。先拒绝不合格候选，再按证据、具体度、基础率风险和反向条件排序；优先跨不同领域选择。`selection_score` 只用于排序，不是命理准确率。

`manifest_sha256` 锁定清单。向用户展示后不得改字、换时间、拆并子项或用反馈替换清单；必须改动时建立新的 `chart_lock_id` 并说明重算原因。

把 `blind_candidates` 和 `blind_manifest` 登记到会话血缘。来源只能包含 `operational_input`、`chart_fact`、`traditional_rule` 和既有 `locked_claim`；检测到 `biography`、反馈、旧报告或 Benchmark 时拒绝。

## 五、用户首屏

一次连续展示默认四条。先给结果，命理依据不默认展开，也不在每条下面堆十神术语。

每条用自然段完成以下信息，不机械显示字段名：

1. 一句清楚结论；
2. 具体时间或现实场景；
3. 可能发生的事情和可观察结果；
4. 必要时列 1–3 个同机制例子；
5. 一句明确反例：现实相反时，这条不成立。

推荐首屏：

```text
盘已经排好。我先不问你的经历，只从命盘里挑四个不同方向。你不用配合我，说“不准”同样有用。

1.〔过去事件：时间窗口 + 场景 + 事件形态 + 可观察结果。若现实相反，这条不成立。〕

2.〔工作或学习：触发场景 + 常见行动 + 结果。若现实相反，这条不成立。〕

3.〔关系模式：进入、承载、边界或退出方式。若现实相反，这条不成立。〕

4.〔资源与选择：机会出现时怎样权衡成本，以及最终可观察选择。若现实相反，这条不成立。〕

你可以直接回复：
1准；2部分准，准在……；3不准；4不确定。
```

不要在首屏展示：

- 候选池、选择分数或技术审计；
- “依据：官杀、财星、印比……”式逐条术语；
- 准确率、命中分数或暗示用户应该认可的语言；
- 四条之外的大段完整命局分析。

用户主动问“为什么”时，可以先给一层白话机制；完整证据链放入最终 Markdown 报告。

## 六、反馈与一次结算

把反馈标签写入机器结算文件。用户自由叙述不原样写入该文件，只提取当前陈述的标签；“部分准”另在 `feedback_log` 中以最小摘要记录究竟准在时间、领域还是结果。

```json
{
  "schema_version": 1,
  "chart_lock_id": "session-001-chart-v1",
  "manifest_sha256": "从清单原样复制",
  "responses": [
    {"probe_id": "probe-work-01", "label": "partial"}
  ]
}
```

标签：

| 用户反馈 | 标签 | 结算 |
|---|---|---|
| 准 | `hit` | 支持当前候选，不外推其他领域 |
| 部分准 | `partial` | 只保留明确命中的轴 |
| 不准 | `miss` | 保留失误并下调，不另找解释 |
| 不确定 | `unknown` | 不支持也不否定 |
| 太宽泛 | `broad` | 零支持权重，回查候选门禁 |
| 之前告诉过你 | `known_fact` | 不得计作盲测命中 |

运行：

```powershell
python scripts/blind_opening.py settle `
  --manifest consultation_state/blind_probe_manifest.json `
  --feedback consultation_state/blind_feedback_input.json `
  --output consultation_state/blind_feedback_result.json
```

脚本结果只控制转场，不在用户面前包装成准确率。结算完成后集中向用户说明保留、部分保留和放下什么，然后直接引入一个主问题；默认不再增加独立画像修正轮。

## 七、转场规则

| `route` | 后续动作 |
|---|---|
| `collect_remaining_feedback` | 提醒未结算条目，也允许用户跳过 |
| `proceed_to_deep_dive` | 简短承接后，从用户话头引入主问题 |
| `proceed_with_caution` | 保留分歧、降低粒度，仍可进入主问题 |
| `recheck_inputs_and_lower_resolution` | 两条以上不准时先核对出生口径；无输入问题则降低推断精度 |
| `continue_without_calibration` | 均不确定或跳过时，按未校准状态继续 |

不要因为需要核对输入就重新让用户做一套盲测，除非盘面输入确实改变并已 `supersede`。

## 八、状态与隐私

- 清单展示前登记 `blind_manifest`，展示后哈希不得改变；
- 机器反馈只保存标签，细节进入最小 `feedback_log`；
- 用户纠正出生输入时先 `supersede --scope chart`，旧清单及下游全部失效；
- 盲测产物不得进入 Skill、示例或 Benchmark；
- 最终报告必须同时保留命中、部分命中、不命中和不确定，不只挑好看的结果。

## 九、验收标准

- 默认四条、最多五条；强信号不足时可以更少；
- 四条来自不同方向，不是同一种性格的换词重复；
- 每条有场景、事件或行为、可观察结果和真实反例；
- 多个例子只解释同一个核心判断，不累计命中次数；
- 首屏先展示结果，技术依据默认隐藏；
- 用户能用 `1准；2部分准，准在……；3不准；4不确定` 一次回复；
- 反馈只结算一次，随后直接进入主问题；
- 不准会真实降低判断，不会被包装成另一种命中。
