# 盲测前完整盘面审计

本文件规定 `chart_ready` 到 `first_read` 之间必须完成的内部分析。它的目标不是向用户倾倒术语，而是先把整张盘的主要结构、冲突、时间窗口和反证分析足量，再从中筛选四到五条现实可验证的盲测。没有活动的 `preblind_analysis`，引导式会话不得进入 `first_read`。

## 一、来源隔离

`preblind_analysis` 只能使用：

- `operational_input`：出生日期、时间、地点、历法和计算口径；
- `chart_fact`：计算器输出的四柱、十神、藏干、关系、大运和流年；
- `traditional_rule`：本技能中明确加载的结构、领域和岁运规则。

禁止读取或继承：用户经历、盲测反馈、关注方向、旧报告、聊天画像和 Benchmark。用户在入口选择的“事业、感情、财运或全部”写入 `consultation_brief`，只能在盲测结算后指导主问题和报告重点，不能影响盲测候选的内容、排序或取舍。

## 二、最低分析深度

内部文件建议命名为 `preblind_analysis.md`，至少包含以下十部分：

1. **计算与边界**：采用的历法、换日、真太阳时、起运口径；分别记录输入确定性、`primary_time_basis`、主盘时柱和候选盘。明确时间的跨口径盘要完整分析主盘，只把会被候选盘改变的内容列为敏感项；真正未知时辰才只做共同结论。
2. **季节与承载**：日主、月令、根气、透藏、生扶、耗泄、制化；元素数量只能作初筛。
3. **结构竞争**：常规格局、从化门禁、扶抑、调候、病药、通关各自在本盘是否成立；至少保留一个竞争解释。
4. **关系变化**：合冲刑害、三合三会、墓库和透干是否真的改变结构，不把单一关系直接翻译成事件。
5. **大运背景**：起运、当前大运、前后运切换，以及稳定支持和主要压力。
6. **主题横扫**：家庭角色、学习路径、工作责任、资源与现金流、关系模式、迁移居住、行为节奏、身心安全八个方向逐项检查。
7. **历史窗口**：至少筛查两个有区分度的过去窗口，写明时间、触发链、可对应的事件类别和不能推出的细节。
8. **未来窗口**：为最终报告准备阶段主题，但不混入尚未发生的盲测命中统计。
9. **疑点清单**：哪些判断互相竞争、哪些信息会改变结论、适合在后续什么时机向用户求证。
10. **候选排序**：为每个现实候选记录证据强度、具体度、基础率风险、反例，以及它是否依赖主盘时柱、候选口径是否会推翻它。不得把所有使用主盘时柱的候选一律降级。

主题横扫不是强行每个领域下结论。若某个领域没有足够信号，必须写“当前不足以形成具体判断”，不能用通用性格话术补空白。

## 三、知识加载

先读 `reasoning-protocol.md`，再按盘面实际疑点加载：

- 旺衰、格局、从化、调候或用神竞争：`structure-analysis.md`；
- 合化、刑冲、三合三会、墓库：`relations-and-transformations.md`；
- 家庭、学业、事业、财务、关系、迁移等现实映射：`domain-rules.md` 对应章节；
- 历史年份、大运切换、未来阶段：`temporal-reasoning.md`；
- 流派或古典口径需要核对时：`classical-texts.md`。

不要为显得全面而一次读取全部资料。每个候选必须能指出实际使用了哪一层规则，并写出最强反证。

## 四、疑点怎样进入对话

盲测前只把疑点记录在内部文件，不先采访经历。盲测结算后再按以下优先级选择主问题：

1. 用户已经主动说出的现实问题；
2. 用户入口选择的关注方向；
3. 盲测反馈中用户愿意展开的话头；
4. `preblind_analysis` 中最能区分竞争解释的疑点。

如果没有明显主问题，可以给用户二到四个值得深入的选择。每个选择在内部都要能回答：为什么值得问、用户的回答会改变哪项分析、需要加载哪一类知识。对用户只说人话，不展示内部打分。

求证的目的不是诱导命中，而是帮助用户辨认现实中的机制。例如，不问“你是不是印旺所以想太多”，而问：“当你迟迟无法决定时，更常见的是信息还没弄清，还是你担心选了以后没有回报？”

## 五、生成与登记

先形成盘面锁，再写内部审计并登记：

```powershell
python scripts/consultation_harness.py register `
  --session-dir consultation_state/<chosen-session> `
  --kind preblind_analysis `
  --path consultation_state/preblind_analysis.md `
  --source-category chart_fact `
  --source-category traditional_rule `
  --source-artifact <chart_facts-id> `
  --source-artifact <chart_lock-id>
```

然后才可以迁移到 `first_read`、生成 `blind_candidates`。候选应以该审计为上游，不得把 `consultation_brief` 作为上游。

## 六、验收

- [ ] 八个现实方向均检查过，弱信号如实留空；
- [ ] 至少一个竞争解释和一个最强反例；
- [ ] 历史窗口有时间边界，不凭某个流年直接指定唯一事件；
- [ ] 关注方向和用户经历没有进入分析血缘；
- [ ] 疑点说明了什么回答会改变判断；
- [ ] 盲测候选来自完整审计，不是临时抓取几个十神；
- [ ] `preblind_analysis` 已登记并保持 `active`。
