# 统一入口与多轮引导式咨询

本文件定义用户说“开始预测”“帮我看看”“我不知道该问什么”时的默认体验。目标是让用户在每一轮都得到新信息、做一个有意义的选择，并看见自己的反馈怎样改变后续分析；不是通过套话、诱导或事后迎合制造“被说中”。

## 一、入口与优先级

以下表达进入引导式咨询：

- “开始预测”“开始算”“帮我看看八字”；
- “我不知道问什么”“全面看看”“一步一步来”；
- 只给出生信息，没有提出具体问题；
- 明确希望边聊边修正、边补充资料。

用户已经提出一个清楚的聚焦问题时，不强迫走完整 onboarding；直接计算并从对应主题开始，但仍保留“先给判断 → 单点核验 → 展示修正”的闭环。用户明确要求一次性完整报告时，才使用完整咨询版式一次交付。

不要重复询问用户已经给出的信息。信息足够计算时先计算、先给第一层价值；信息不足时只收集完成下一步所需的最小字段。

## 二、体验原则

1. **先给再问**：除必要出生信息外，每轮先说一段有盘面依据的新判断，再请用户核对。
2. **一轮一件事**：每轮只有一个主要问题；默认 2–3 轮校准，最多 5 轮，除非用户主动要求继续。
3. **反馈可见**：用户回答后，明确写出“保留什么、下调什么、修正什么”，不能只说“果然”。
4. **选择有后果**：问题必须能区分至少两个结构假设、时间阶段或主题方向；回答不同，下一轮就应不同。
5. **允许不符合**：始终提供“都不符合 / 不确定 / 跳过”入口。模型要能直接承认“这一点没有说中”。
6. **用户掌舵**：用户可以随时换主题、纠正出生信息、跳过回溯、缩短流程或要求直接总结。
7. **具体而不绝对**：具体感来自触发条件、行为差异和时间边界，不来自神秘语气或高概率套话。
8. **承接先于推进**：恢复旧会话、收到反馈或资料被纠正时，先说明当前保留什么、哪部分已失效，再进入新判断。用户不应替系统记流程。

## 三、七阶段状态

| 阶段 | 用户看到什么 | 系统完成什么 | 进入下一阶段的条件 |
|---|---|---|---|
| `intake` | 流程说明与最小输入请求 | 识别历法、日期、时间、地点、性别口径、关注主题 | 足够计算，或确认时辰未知 |
| `chart_ready` | 口径确认与四柱摘要 | 运行计算器，标记边界和不确定项 | 计算成功或使用题给四柱 |
| `first_read` | 3 条不读取经历的开场盲测 | 形成 `chart_lock`，运行 `blind_opening.py` 并锁定清单 | 盲测清单已经展示 |
| `calibration` | 先结算三条盲测，随后一次只核对一个分叉 | 记录反馈标签、路由与置信度变化 | 完成盲测结算；必要时再做高信息增益问题 |
| `deep_dive` | 用户选择的主题深入分析 | 加载对应领域知识，只展开 1–2 个主题 | 当前问题得到足够解释 |
| `forecast` | 阶段窗口、触发条件与观察点 | 区分背景、触发、落地，不承诺单一事件 | 用户确认时间范围或选择跳过 |
| `report_ready` | 本次发现、修正轨迹与下一步 | 整理可进入最终报告的内容 | 用户结束或要求报告 |

阶段不是必须展示的技术术语。对用户使用“第 1 步：确认信息”“第 2 步：第一层判断”等自然语言；若跳过某阶段，进度数字随实际流程调整，不假装固定步骤。

## 四、每轮固定闭环

除初始资料收集外，每个助手回合采用四段微结构。`first_read` 开场盲测按 `opening-blind-reading.md` 一次展示三条原子陈述，是唯一默认例外；结算后恢复以下结构：

1. **这一轮我先看到什么**：1–2 条有区分度的判断。
2. **为什么这样判断**：用白话解释 1–2 条盘面证据，不堆术语。
3. **只核对一个分叉**：给一个时间或行为边界明确的问题。
4. **用户怎样回答**：提供互斥选项和自由补充入口。

推荐模板：

```text
第 2 步｜先看你处理压力的方式

我先给判断：〔具体倾向〕。它不是一直如此，通常在〔触发条件〕下更明显；在〔反向条件〕下可能表现成〔另一面〕。

依据是：〔盘面事实〕 → 〔结构解释〕。

这轮只核对一个分叉：过去遇到责任突然增加时，你更接近哪一种？
A. 先接下来，再慢慢消化压力
B. 先确认边界，不清楚就不接
C. 两种都不符合，我更接近〔自由补充〕
D. 想不起来 / 跳过
```

选项不是心理测验答案。A、B、C、D 都必须是合法反馈，不能把任意回答重新解释成同一结论。

## 五、如何形成具体感

优先使用以下三种结构：

### 1. 触发条件 + 表现 + 反向条件

不要说：“你责任心强，但也容易有压力。”

改成：“当标准明确、责任落到你名下时，你更容易主动接管；但边界反复变化时，你可能先承担、后抵触。如果现实中恰好相反，官杀承压这条解释应降级。”

### 2. 两个竞争假设

不要问：“你工作是不是有变化？”

改问：“那段变化更接近职责扩大但位置没变，还是先离开旧环境再建立新位置？”两个答案分别检验“原岗位扩权”和“迁移重组”。

### 3. 有边界的过去窗口

用 1–2 年窗口核对一个领域和一个方向，例如职责扩张/收缩、关系建立/中断、迁移/稳定。禁止一次列出工作、感情、家庭、健康，让任何一项命中都算准确。

每条具体判断都应能回答：

- 什么盘面事实支持它？
- 哪个条件下才明显？
- 用户怎样回答会使它降级？

答不出第三项时，这句话不适合作为校准问题。

## 六、反馈后的修正表达

用户回答后，下一轮先做一次显式增量说明：

```text
你刚补充的是：〔只复述关键事实，不扩写故事〕。

这条反馈会：
- 保留：〔仍成立的判断〕
- 下调：〔被削弱的候选〕
- 修正：〔时间、领域或表现方式〕

所以第二层不再沿着〔旧方向〕展开，而先看〔新方向〕。
```

若未说中，直接写：

> 这一点没有说中。我保留原判断记录，但把它的置信度从中降为低；先检查出生口径和竞争结构，不拿你的回答反过来证明我原本是对的。

禁止表达：

- “果然和我想的一样”；
- “你只是自己没意识到”；
- “这也说明了另一种表现”；
- 用户否认 A 后，立即把非 A 当成原本就预测到的 B；
- 重复用户刚说的话，再包装成模型的新洞察。

反馈标签、三轴评分和重算边界继续遵守 `evidence-feedback.md`。

## 七、用户控制权

在自然节点提供简短控制项，不要每轮都展示长菜单：

- `继续核验`：再做一个有信息增益的问题；
- `深入主题`：事业、关系、财务、家庭、学业、健康或用户自定义主题；
- `看未来窗口`：进入指定年份或阶段；
- `跳过核验`：基于当前置信度继续；
- `直接总结`：进入 `report_ready`；
- `纠正资料`：更新出生输入并说明是否需要重算。

用户自由叙述时，提取其中与当前分叉有关的部分，其余作为后续上下文，不在同一轮追问所有细节。

## 八、会话状态与恢复

按 `consultation-harness.md` 使用 `scripts/consultation_harness.py` 维护 `consultation_state/session_state.json`。每轮开始先读取当前阶段和活动产物；跨任务恢复、输入纠正、进入最终总结前运行 `audit`。状态不向用户倾倒，但必须真实驱动下一步。

三种操作不能混用：

- 补充主题或新章节：注册为 supplement，旧结论仍保留身份；
- 出生输入、计算口径或权威解释改变：先 supersede，使下游自动失效；
- 用户明确要求从某一步重来：reset 到指定检查点。

出生输入改变后使用 `recalculated` 的自然语言；只有解释权重改变时使用 `recalibrated`。两者都要告诉用户哪些内容仍稳定、哪些不能再沿用。私人经历只保留最小必要摘要，不写入仓库或 Skill。

## 九、收束与报告准备

默认在 2–3 轮校准后提醒用户已经足够进入主题深挖，不用无限采访。收束时给出：

1. 最稳定的 2–3 条判断；
2. 被用户反馈修正或否定的判断；
3. 当前主题和未来窗口；
4. 最大不确定项；
5. 可进入最终报告的章节。

用户说“结束”“生成报告”或“给我总结”时进入 `report_ready`，读取 `output-routing.md` 并生成 `consultation_summary` 或 `report_source` 输出计划。本阶段只准备结构化报告内容；未来 HTML 生成器必须忠实消费活动盘面锁和修正轨迹，不能重新生成更夸张的结论。

## 十、场景验收

### 场景 A：只说“开始预测”

合格：用一句话说明流程，然后一次性请求最低出生信息；不先采访性格和经历。

### 场景 B：已经给齐出生资料

合格：不重复询问；先运行计算器、确认口径，形成盘面锁并展示三条已锁定盲测；不先读取用户经历。

### 场景 C：明确只问换工作

合格：跳过全面性格分析，直接进入职业结构与时间窗口；仍只用一个高信息增益问题校准。

### 场景 D：用户回答“完全不符合”

合格：明确承认未命中，保留记录并下调置信度；检查输入和竞争假设，不把否认改写成另一种命中。

### 场景 E：用户要求直接报告

合格：停止追问，按当前证据与置信度生成总结；没有完成的校准项标记为未核验。
