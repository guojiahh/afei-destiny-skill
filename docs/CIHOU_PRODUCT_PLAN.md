# 此后产品形态与体验方案

更新：2026-10-16。第一阶段已完成并获用户确认。本版统一此前方案：**每次完整咨询都交付同一种莫比乌斯环 HTML，固定视觉、交互和阅读骨架，按本次咨询重新写内容。** 多图型与自动选图不再是现役要求。开发入口见[交接说明](CIHOU_HANDOFF.md)，实现合同以 [HTML 协议](../afei-destiny-skill/references/html-report.md)为准。

## 产品要回答什么

此后是一份可以阅读与探索的个人咨询报告，围绕一个主要矛盾回答：过去有哪些因素、现在在哪里、为什么可能持续、下一步能做什么、未来还依赖哪些条件。其他生活领域保留分析与未知，不与主图争夺重点。

核心表达是：即使人生受到既有条件影响，思考、选择和行动仍然会成为塑造未来的原因。与此同时，他人、制度、资源与环境也是原因；行动不保证成功，困局也不等于个人不够努力。

传统四柱八字保留为观察框架。历法计算、传统解释、当事人叙述与咨询推断分别保留来源；命盘不能证明人格形成的科学因果，也不能补写未经提供的经历。

## 从咨询到交付

| 环节 | 用户体验 | 当前实现 |
|---|---|---|
| 进入 | 新开或继续一次咨询 | 发现会话并明确选择，资料互不混用 |
| 了解 | 提供必要信息，核对开场判断 | 计算、锁定、反馈与来源防火墙 |
| 深入 | 围绕一个现实问题，讲清需要和约束 | 保留真实事例、支持、反例与未知 |
| 形成报告 | 收到一份完整个人 HTML | 先双底稿，后来源绑定模型与页面 |
| 首次打开 | 看一句具体理解，直接点击主图 | 路上、全环、跨出三个状态 |
| 继续阅读 | 自然向下，读完整次咨询 | 固定九章正文、末尾完整依据 |
| 纠正与回访 | 回到原对话说明变化 | 由咨询重新分析并生成新版本；页面点击不修改咨询状态 |

原有 `guided`、`focused`、`one_shot` 模式继续保留。短回答和简短总结不被强制扩展成完整报告；一旦交付完整报告，默认使用 HTML，只有用户明确只要 Markdown 时例外。已经授权报告时不再追加确认关卡。

## 统一主图，不统一人生解释

所有新报告共用暖白背景、深灰纸带、宋体标题、朱红人物，以及同一套构图与三态动作。无需每次生成新图片或寻找新图型。

| 固定 | 每次重新编排 |
|---|---|
| 莫比乌斯环几何与人物路线 | 本次问题、已知经历、现实约束 |
| 路上 → 全环 → 跨出的顺序 | 每个状态的两行标题与一句解释 |
| 点击主图、暂停、重看 | 本人可以尝试的行动及必要条件 |
| 九段正文与六类排版 | 具体事例、反例、领域深度、反馈修正 |
| 依据区、来源索引与下载 | 当前会话的计算、解释与原始底稿 |

环是困局的视觉隐喻，不是“此人已经被证明陷入心理循环”的结论。材料不足时，第二态可以说“反复来自哪里，还需要核对”；外部条件主导时，解释限制与可争取的支持；暂时没有合适行动时，跨出可表示停止重复一种无效解释，转而观察、求助或保留选择。不能用同一套求职、拖延或过度准备文案套所有人。

只有有来源的关系才进入模型。没有支持时可以不连边，使用 `unknown` 节点；图的共同形状不授权虚构过去。反例成立时修改解释和行动，仍保留同一视觉模板。个人化首先是内容准确，而非形状随机变化。

## 主图怎样让人理解

1. 路上：从当事人的处境出发，一句具体话说明原有做法为什么有意义。
2. 全环：拉远看一种可能持续的机制或尚未解释的困境。人物循环行走，文字承接本次材料。
3. 跨出：人物从前侧走向页面留白，旧环保留。说明一个可选择的改变及其条件，不播放“已获回应”的成功结局。

图内大范围点击，标题和解释在固定位置同步替换；正文始终可下读，无弹窗、跳转或必须看完动画的门槛。暂停、重看、键盘、离屏暂停、减少动态和无脚本正文均保留。

当前实现是两张透明 PNG、SVG 人物路径与淡化，不是同一 3D 空间连续运镜。视频或实时 3D 只属于后续画质优化候选，不是完成每次报告的依赖。

## 固定的报告结构

双底稿是完整内容源：用户报告八节，技术报告十一节，分别按固定模板完成。HTML 按阅读需要编排为九章，不直接平铺两份长文。

| 顺序 | 章节职责 | 主要表现 |
|---|---|---|
| 1 本次主问题 | 当前处境、来处、需要与最重要理解 | 叙述与对照 |
| 2 困局如何持续 | 已知联系、关系假设和未解之处 | 过程路径 |
| 3 现实中的具体场景 | 用本次事例或明确的条件式例子检查解释 | 场景与反例 |
| 4 一个可尝试的改变 | 介入点、步骤、条件和可观察证据 | 有限步骤 |
| 5 路径与取舍 | 按实际状态选择，说明成本和外部条件 | 对照排版 |
| 6 未来与观察窗口 | 现实实验及传统窗口，明确区分 | 时间带 |
| 7 其他生活领域 | 自我、学习、事业、财务、关系、家庭、迁移、身心 | 主题短解读 |
| 8 反馈与修正 | 原判断、实际反馈、保留与撤回 | 反馈列表 |
| 9 边界与下一步 | 置信边界、重要缺口、收束 | 连续短文 |

章节职责与顺序固定，标题、卡片数量与篇幅按人调整。没有谈到的领域写未展开，没有做过开场核验就写未核验，不为填格子制造信息。关键反例与限制放在相关正文旁；完整双底稿集中在页尾按节展开，并可下载。

## 工程保证

```text
本次咨询活动来源
  → 各自来源计划
  → 用户八节底稿 + 技术十一节底稿
  → 校验并登记双底稿
  → 初始化 cihou-mobius-v1 模型草稿
  → 填写本次三态与九章内容，复核来源
  → 预览、生成、登记 HTML
  → 确定性检查 + 会话审计 → 完成
```

新会话记录固定模板身份。模板缺失、章节丢失或乱序、草稿占位符未清、跨会话来源、旧哈希或缺少底稿都会阻止有效交付。最终 HTML 登记需要与渲染结果一致，不能随手拷一份演示文件充当报告。脚本不自动推理人生，也不替代人工语义复核。

HTML 的图片、CSS、JS 和原文下载全部内嵌，可离线使用。历史模型继续可检查和重现；旧多图型渲染器是兼容层，不再用于新报告选型。已登记版本先失效再新建，旧文件留存，离线副本不会被远程撤回。

## 第一阶段完成范围

完成并获得用户认可的是本地个人报告体验和流程：安静的纸面视觉、三态主图、持续行走、完整报告、固定模板、来源登记及同页依据。已以用户指定的一次完整咨询落地；新增模板门禁通过合成资料回归。

桌面与 320／390px 浏览器视口检查支持当前排版与交互结论。尚未完成实体手机文件接收和打开测试，也没有独立首次用户理解度数据；不把用户确认或代码通过包装成普遍效果验证。

## 第二阶段候选范围

本轮不直接启动第二阶段。建议先解决“生成后怎样真正到达用户手机”，再决定回访与传播功能。

- 私有阅读：选择受访问控制的托管与身份方案，用户授权后才上传私人报告，提供版本识别、撤回与删除。
- 真机体验：至少一台 iPhone 和一台 Android 验证获取文件或链接、点击、长文与离线状态。
- 回访与纠正：先通过原对话处理；再设计观察记录导出和版本差异，不把浏览器草稿当成已保存咨询。
- 脱敏分享：从用户明确选择的少量字段另行生成图片；不能仅在完整 HTML 中隐藏个人信息就称为脱敏。
- 理解测试：观察读者能否说清问题、改变与条件，尤其是否把动画当作命运保证。小样本用于改进，不宣称准确率。

账号、云端保存、报告集合、跨设备同步、网页内完整咨询与提醒均未实现。提醒须由用户主动选择。没有新反馈时，不按日期自动生成“人生进展”。
