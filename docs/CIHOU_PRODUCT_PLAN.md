# 此后产品形态与体验方案

初稿：2026-10-15。更新：**2026-10-16 默认 HTML 交付接入版**。第二阶段的本地生成与登记已落地，私有在线交付仍待建设。

> 第一阶段匿名样机的体验是“直接点主图不同位置＋同一处短解说＋连续下读”。循环型已加入立体轨道、任务累积、行动拨片与约 16 秒自动讲解，点击可随时接管；接桥、汇流与留白保留上一版图形。详报补入决策场景、反例和默认可见的八领域覆盖。当前效果见[独立 HTML](../design-demos/cihou-stage1.html)，实际能力和验收见[原型说明](../design-demos/cihou-stage1/README.md)，新对话从[交接说明](CIHOU_HANDOFF.md)开始。当前正式流程以 [HTML 报告协议](../afei-destiny-skill/references/html-report.md) 为准：双底稿 → 咨询代理编排个人模型 → 校验生成与登记 HTML。手机私有托管、全自动选图与回访同步仍未实现。

第一阶段四例为人工定制样机，不能只换姓名或 `cases.js` 就给另一位用户使用。同型多人物、任意节点布局和按咨询自动选图尚未实现；完整内容组织与类型选择见[主图与完整报告体验方案](CIHOU_REPORT_EXPERIENCE.md)。


「此后」是一份可以探索、校正和回看变化的个人交互报告。它帮助用户理解哪些经历和条件把自己带到此刻，试演一个行动可能改变什么，并把新的现实反馈带回理解之中。品牌表达延续：**你的选择，也在塑造未来。**

以现有 Skill 的咨询流程为入口，默认交付一份手机优先的个人 HTML，双 Markdown 为内部底稿和可选下载。当前本地文件可离线阅读；后续再增加受访问控制的手机链接、回访与版本更新。每个人共享品牌、阅读方式和视觉规则，自己的经历、重点问题、关系结构与选择决定画面。主图集中表达本次最重要的一个问题，完整的人生内容保持可读、可查。

## 一 当前产品基础与升级范围

### 已有能力

现有产品的运行环境是 Codex Skill。默认咨询经过资料确认、计算、开场判断、一次反馈、主问题深入、未来展望和报告准备；也支持聚焦咨询、一次性完整解读。默认主交付是同一会话登记的 `final_report.html`；`final_report.md` 和 `technical_analysis.md` 保留为底稿。个人模型、HTML 生成与校验、来源登记、下游失效及完成条件已接通。[现有流程](../afei-destiny-skill/references/guided-consultation.md)、[输出路由](../afei-destiny-skill/references/output-routing.md)

[当前此后演示](../design-demos/cihou-stage1.html)包含循环、接桥、汇流与信息不足四个匿名虚构样例；循环型可自动讲解、点图接管并在行动后等待回应。现有验证覆盖脚本、桌面和手机响应式视口，尚无真人理解度与实体手机验收。[早期单例概念](../design-demos/cihou.html)与[海图第五版](../design-demos/report-v5/README.md)保留作历史对照，均未接入正式咨询。

### 产品形态建议

| 层次 | 用户得到什么 | 建设顺序 |
|---|---|---|
| 咨询入口 | 在现有对话中讲清问题、核对经历、形成理解 | 继续使用现有 Skill |
| 个人交互报告 | 本次主图、条件试演、完整图文与可展开依据 | 本地 HTML 已接通；私有阅读链接后续建设 |
| 观察与回访 | 带走一个问题或行动，回来补充发生了什么 | 首期通过原对话承接，后续再直接联动 |
| 个人报告集合 | 按主题与时间查看几次咨询，比较解释怎样变化 | 多次使用需求成立后再做 |
| 完整在线产品 | 浏览器内咨询、个人报告集合与完整账户服务 | 后续独立阶段；首期手机阅读所需的访问控制先实现 |

正式用户默认进入自己的报告。演示中的人物切换器只用于展示样例；个人 HTML 不内嵌其他人的内容。一个用户可以有多份不同主题的报告，每份报告也可以有多个版本。跨咨询合并需要用户明确选择范围，不能因为出生信息相同就自动拼成一份人生档案。

## 二 核心价值与内容重心

报告要让用户逐步回答五个问题：

1. 我经历过什么，哪些信息已经能够确认？
2. 我现在处于什么位置，有哪些资源和限制？
3. 对眼前处境，目前有哪些有依据、也允许被修正的理解？
4. 我能尝试什么，每一种选择需要什么条件、会付出什么成本？
5. 接下来出现什么反馈，会让我改变原来的判断？

首屏只选择一个最值得理解的核心关系。事业、关系、家庭等全景仍在完整报告中，但不同时变成主图上的所有节点。主图的任务是让用户迅速抓住重点；详细图解负责展开关系、反例和出处。

产品也应容纳单纯想理解自己的人。用户可以只阅读、纠正一段理解、保留一个观察问题，暂时不制定行动。维持现状、等待更多信息、保护已有积累，都可以是合理选择。

### 八字在产品中的位置

保留现有产品的传统文化分析入口，并清楚区分三种内容：计算得到的历法事实、传统规则给出的解释、用户提供的现实经历。八字解释可以提供观察角度和阶段主题；个人经历及其关系不能仅由出生资料推导后伪装成已经发生的事实。

“来处”只展示有来源的经历；“为什么会这样”展示可修正的理解；“此后”分别呈现现实行动的条件推演与传统解释下的阶段展望。两者有联系时说明联系，有不同来源时保留区别。未来窗口只有在源报告提供相应依据与粒度时才显示日期，不生成精确的事件倒计时。[报告规范](../afei-destiny-skill/references/markdown-report.md)

## 三 完整用户旅程

### 从对话到第一次打开

首次接触者可以先玩一个公开的匿名样例，再进入现有 Skill 咨询入口。样例只帮助理解产品，不要求提交个人资料；它也不会打开其他人的私人报告。首期仍面向由 Skill 完成咨询的用户，浏览器内直接发起完整咨询留到后续阶段。

| 环节 | 用户看到与操作什么 | 系统如何承接 |
|---|---|---|
| 进入 | 说出关注的问题，或选择新开、继续一次咨询 | 沿用已有会话发现与选择，不混合历史会话 |
| 了解 | 提供最小必要资料，按当前模式完成分析和反馈 | 不额外增加长问卷；聚焦与一次性模式保持可用 |
| 深入 | 围绕一个重点问题补充经历、成本与约束 | 每轮只问一个能改变理解的问题 |
| 收束 | 看见简短总结，知道这份报告会重点讲什么 | 沿用已有报告授权；此前已要求报告时无需再次确认 |
| 生成 | 双底稿、个人模型和 HTML 校验登记完成后得到「打开你的此后」入口 | 生成过程区分分析、资料整理、报告绘制，不显示伪造的分析百分比 |
| 打开 | 看到自己的主问题与一张可直接点选的主图 | 首次可播放短讲解，任意点图即可接管；图下同一处解释随焦点变化 |

不新增强制的“整张图逐项确认”关卡。一个会影响结构的重要疑点，可以放进现有深聊中的最后一问；其他修正入口留在报告里。这样保留对话的自然感。

### 进入报告后的阅读方式

**来处、此刻、此后**是同一张图中的阅读含义，不是三个切换入口。相关位置同时可见，可直接点图探索，不用先看完过去才能理解未来。

| 阅读含义 | 图上发生什么 | 用户可做什么 |
|---|---|---|
| 来处 | 依次显现与本次问题有关的经历，保留其时间顺序 | 点一处经历查看原意与来源；时间不明则不补年份 |
| 此刻 | 相关条件汇聚到当前位置；突出一种主要关系 | 查看资源、限制、可能的理解与反例；提出纠正 |
| 此后 | 露出可以介入的地方与尚未确定的连接 | 选一个具体行动，查看条件分支、成本和观察点 |

点选时保留主要形状和阅读位置，让相关部件、路径与短解释同步变化。当前循环样例的首次讲解约 16 秒，支持暂停、继续和重播；点击立即接管，其他样例保留直接探索。后续分镜长度由本次内容与理解测试决定，不要求所有人的动画相同。

### 一次预演的完整过程

以匿名虚构的职责问题为例：

```text
原有关系：经常补位 → 逐渐形成默认职责 → 临时任务再次交给我

我的行动：提出任务清单，沟通优先级与交接
                     ↓
新条件：原来未经讨论的安排，成为可以协商的问题
                     ↓
等待现实回应
          ↙                         ↘
如果愿意协商                   如果未获同意
确认延期和交接安排             补充负荷与交接条件
观察安排是否落实               再决定重谈、等待或探索其他路径
```

操作只展开当前选择下一层的条件，最多同时重点比较两到三条有依据的分支。更长的过程按需逐层展开，避免生成一棵铺满屏幕的未来树。每条路径都能看见“需要什么”“可能付出什么”“下一步观察什么”；不直接跳到成功、幸福或失败的终点。

“试演对方回应”与“选择自己的行动”在界面上明确分开。用户可以控制自己的尝试，无法点击决定他人现实中的回应。纯观看、想尝试、已尝试、实际反馈是四种不同状态，不能互相自动转换。

### 离开与回访

用户离开前可以保存一张简短观察卡：自己选中的行动或问题、成立条件、一个待观察信号。例子是“讨论职责后，哪些安排实际改变了？”用户也可以选择先不行动。

首期的“带回咨询”导出或复制一段带报告版本的观察记录，由用户在原对话中提交。静态 HTML 不声称已经同步、预约提醒或自动记入咨询。仅存在浏览器中的草稿应明确提示未保存，不能把浏览器临时存储作为唯一记录。

回访从“发生了什么”开始，接受没行动、没有变化、情况更复杂等反馈。更新后显示“新增了什么事实、哪段理解被修正、哪些仍未知”，保留旧版本。没有新反馈时，图不会随着日期自动长出进展。

## 四 每个人为什么会得到不同的页面

### 固定与变化的边界

| 固定的产品规则 | 由本次内容决定的部分 |
|---|---|
| 品牌、字体、材质、操作位置 | 报告主标题、重点问题与情绪语气 |
| 来处、此刻、此后的阅读方式 | 经历数量、顺序、时间范围与缺失信息 |
| 事实、理解、试演的区分方式 | 哪些节点可信，哪些关系有争议 |
| 点击、暂停、查看依据、提出纠正 | 装置的连接结构、当前重点和可介入位置 |
| 移动端触控与无动画阅读 | 行动数量、外部条件、后续分支和观察问题 |
| 分享与版本规则 | 下方主题深度、资源、反例与修正记录 |

个性化由内容形成，不通过随机颜色、装饰或额外节点制造差异。同一份内容应稳定得到同样的结构；反馈改变后，只修改受到影响的部分，避免用户每次打开都面对完全陌生的图。

### 当前四类样例与后续结构

这些结构是绘图方法，不是四种人格类型。一个人可以有几种关系同时存在，主图优先表达与本次问题最相关的一种。

| 结构 | 内容条件与匿名例子 | 主要画面 | 一次有意义的操作 |
|---|---|---|---|
| 反馈环 | 用户描述反复补位，也观察到职责逐渐默认 | 一个有来路、有出口接口的回环 | 加入一次优先级沟通，显示新的协商条件 |
| 接桥 | 已有练习或作品，但缺少明确标准和具体反馈 | 两段轨道之间保留反馈条件的空隙 | 提出具体反馈请求，保留反馈者与用途仍待确认的条件 |
| 汇流 | 专业方法、合作关系和持续积累，共同支撑当前机会 | 几条各有来源的轨道汇入同一平台 | 比较保护现有主线与尝试组合需要的不同条件 |
| 留白／并置 | 仅知想换节奏、暂不决定，尚不清楚处境与原因 | 少量已知表达保持未连接 | 查看已知与未知；不预设压力、性格原因或未来路径 |

开放传导关系也是必要结构：例如林舟 V2 的岗位空缺与明确派工，不应继续解释为个人循环。目前仅在修正对照中表达；完整新版开链主图仍待设计。后续类型库见[报告体验方案第 8 节](CIHOU_REPORT_EXPERIENCE.md#8-主图类型库同一套语言按内容换结构)。

没有足够信息时，展示两项已知条件与一个未解问题也可以成立。不能为了完成一个漂亮的环，补写用户没有说过的经历，也不能把稳定积累的人强行描绘成被困住的人。

首屏宜只突出少量关键短标签，全部相关内容在下方正文承接。节点数量来自资料，热点数量属于阅读设计，两者分开处理；当前样机的 6 或 4 个热点不代表固定的事件数。任意节点数量的自动排布尚待实现。

### 个性化生成规则

当前正式链路由咨询代理从活动底稿编排个人节点、关系、来源和分镜，脚本校验并绘制。支持 2–12 个重点节点，额外内容在详报展开；全自动语义选图和所有类型的精修仍待扩展。匿名样机不是正式生成器。

先提取已登记报告中的经历、资源、约束、理解、行动和条件；再判断哪些关系有足够依据表达；最后选择合适的布局。若几个解释并存，默认呈现当前最有支持的一种，并提供“另一种理解”。用户提出“不太对”后，修正流程可以改变关系、移除连接或改变布局，而非只修改一句标题。首期页面先记录纠正草稿并标记待处理位置；用户把反馈带回原咨询，分析与报告更新完成后，下一版本才呈现正式结构变化。页面内的模拟变化不得显示为已经重新分析或同步保存。

节点来源与连线依据分别记录。两件事都发生过，并不意味着一件导致了另一件；用户认可描述，也不证明整条关系已经被科学验证。

## 五 完整页面结构与图文解读

### 首屏

首屏保留品牌「此后」，把主要标题留给用户本次的问题或理解。例如“从默认承担，到重新协商”；品牌句“你，也是原因”可以在开场与结尾出现，不占据每份报告相同的全部标题位置。

首屏的基本构成是：一个个人化标题、一张可点选的主图、一处同步短解释，以及必要的播放控制。主要操作直接发生在图内。具体名字可用匿名称呼；出生信息、技术参数、置信度表格不占据这里。当前理解与关键未知保持可读，详细依据沿正文继续阅读。

### 首屏之后

保留自然向下阅读，不把每一段都藏进需要反复点击的弹窗。以下模块由已有报告章节转换，文字配合有信息含义的图形：

| 内容 | 建议表现 | 阅读重点 |
|---|---|---|
| 本次最重要的理解 | 二至三幅关系小图，各配一句结论 | 哪些资源与压力共同塑造眼前处境 |
| 重点问题 | 主图局部放大、具体场景、反例对照 | 在什么情况下成立，在哪些情况下不成立 |
| 人生全景 | 主题目录与各自的小图；一次突出一个主题 | 与本次问题有关的联系及尚未了解的部分 |
| 当前与未来窗口 | 按已知时间范围展开的时间带 | 阶段主题、机会、条件、准备；区分传统解释与现实计划 |
| 选择与取舍 | 两条路径并列比较，手机上下排列 | 保护什么、投入什么、依赖什么 |
| 反馈与修正 | 原判断、收到的反馈、当前理解的变化图 | 保留、修正、放下与仍待确认 |
| 技术依据 | 独立入口或按需展开的文字阅读 | 核对计算和传统推导 |

完整咨询继续覆盖既有八个主题：自我、学习、事业、财务、关系、家庭、迁移、身心。未深入的领域明确显示当前覆盖程度；不补齐八张看起来一样饱满的卡片。聚焦回答按原模式处理范围，不为展示完整而强迫扩展咨询。

### 手机交互

主图按手机重新排布，关键连接保持可读，避免只缩小桌面画布。首屏核心操作在常见窄屏中可达；标题约 28 至 40 像素、正文以 16 像素左右为起点、按钮至少 44 像素高，具体字号在下一轮样机中实测。

节点解释在图下同一处更新，不再弹出需要关闭的面板。来处、此刻、此后均可直接点选，复杂内容无需精确拖动或双指操作。提供键盘操作、屏幕阅读器摘要和减少动画后的静态状态。

## 六 独特视觉风格

### 风格方向

当前采用暖白纸面、墨色中文标题、蓝色有厚度的回环与铜橙行动拨片。立体感集中在轨道切面、前后遮挡、任务叠层与转向处，文字保持平面清晰。其他三类图暂保留线束表达，后续逐类设计，不要求每个人都长成同一件环形装置。

辨识度来自稳定的三个特征：有开口的器物轮廓、铜色的可介入部件、一次清楚的接合或转向动作。分享出去即使不带完整界面，也能认出这是「此后」。

### 视觉语法

| 元素 | 承担的含义 | 约束 |
|---|---|---|
| 有痕迹的实心轨道 | 用户讲述且有明确来源的经历、现实条件 | 不把材质真实性当作因果证明 |
| 单独标明的连接 | 对经历之间关系的一种理解 | 可查看条件、出处与反例，可被修正 |
| 铜色拨片或接头 | 用户可以考虑的一次具体行动 | 不代表点击后已经在现实行动 |
| 未接合的空隙 | 缺少信息、外部条件或尚待回应 | 不为美观自动闭合 |
| 轻质轮廓的未来路径 | 条件成立时可以继续探索的情景 | 不把透明程度映射为成功率 |
| 沿线移动的光点或小球 | 正在阅读的线索 | 不把人描绘成只能被机器推动的物体 |

实际配色以[当前样式](../design-demos/cihou-stage1/styles.css)与[主图源码](../design-demos/cihou-stage1/scene-kinetic.js)为准。初稿的墨绿陶瓷方案已由当前纸白、蓝色轨道与铜橙介入替代。颜色配合文字或形状，避免将绿色等同好运、红色等同厄运；各分支都保留继续观察的空间。

早期概念中的绿色勾容易让“愿意协商”被读成通关，当前版本已移除。后续继续避免成功与失败的装饰性对照；双方的回应只是后续条件不同。

### 字体与动效

中文标题采用清楚的宋体风格，正文与按钮使用易读黑体；短句、字号和留白建立层级。图形可以有质感，图上的字保持清晰平面，不能为了艺术感降到难读的透明度。

每个动效都回答一个问题：这段从哪里来、哪项行动介入、哪个条件改变、在哪里需要等待。保持固定视角，先变化部件，再变化相连路径；一次动作完成后停下来。声音默认关闭，首期不依赖声音传达信息。

当前用原生 SVG 与 CSS 表达空间感，避免把个人内容烘焙成图片。正式接入时需让文字、轨道与交互从同一份个人结构数据生成；现有循环几何与分镜仍是人工设定。图像生成可用于探索材质、封面和造型；真实 3D 渲染在证明能提升辨识或理解后再局部引入，并保留静态阅读方式。

### 参考作品与借鉴范围

[Dear Data](https://www.dear-data.com/theproject)把每周个人生活资料画成明信片，并在另一面给出读图说明。对「此后」的启发是：个人内容可以形成有记忆点的作品，同时保留可核对的解释层。

[Spotify 2025 Wrapped 的官方设计说明](https://newsroom.spotify.com/2025-12-03/wrapped-marketing-campaign/)以私人混音带的文化形式组织个人听歌故事。这里值得借鉴的是统一品牌容纳个人故事与分享表达；「此后」不需要引入排行榜或未经依据的人生分数。

[Nicky Case 的互动解释方法](https://blog.ncase.me/how-i-make-an-explorable-explanation/)强调先让读者经历具体操作，再理解抽象关系。对应到「此后」，哲学表达由一次真实可理解的交互承载，长篇解释放在用户愿意深入的位置。

上述方向属于设计借鉴，不复制作品的资产、角色或关卡语言。

## 七 需要提前解决的产品问题

### 解释的说服力与可修正性

画面越漂亮、动作越流畅，越容易让用户把一种理解当成已经证实的因果。每个核心关系提供轻量的“为什么这样画”和“这不太符合我”入口；纠正经咨询处理后，用户应在新版本中看见图形与解释真的改变。首期静态页中的纠正是待导出的草稿，生效时点明确显示。

节点细节分别展示用户描述、当前理解、仍不确定的条件。开场判断原文及不符合的反馈继续保留。确认经历不自动提高命理准确率，也不将过去得到反馈的判断重新写成事先已知。

### 主动权与责任

“你也是原因”同时承认他人、制度、资源和环境也是原因。图中要看得见不可由用户单独控制的条件；不能把困境解释成用户没有努力、选择不够正确或没有及时改变。

行动可以带来新信息，也可能暂时没有改善处境。选择等待、求助、减少投入、保持稳定都应有位置。回访不使用打卡失败、退步或负分评价。

### 阅读完整性

主图重点突出，但用户必须仍能读到完整报告和最强反例。不能只选容易形成漂亮故事的内容，也不能把未知领域悄悄删除。图形不足以表达的限定用短文字说明；每一段文字不必硬变成图表。

### 分享与隐私

私人完整报告与分享作品分开生成。分享页或图片只取用户选择的主图与短句，默认不包含出生资料、精确日期、关系人物、原话、完整经历或技术报告。生成前展示预览，允许用户删掉任何不愿公开的部分。

不能只在完整 HTML 中隐藏信息后就称为脱敏，数据仍可能存在于文件源代码中。分享产物应从明确允许的少量字段重新生成，文件名与元数据也不包含私人信息。本地副本保留在用户设备中。开通手机在线阅读时，明确告知上传目的地与内容范围，得到用户授权后才上传；报告默认私有。分享授权与私人阅读授权分别处理。

### 版本与回访

报告显示生成日期与版本，记录它依赖的来源版本。新反馈影响了理解时，旧图保留为当时版本，新版本说明变化。用户下载的旧 HTML 无法自动撤回或更新，页面不能声称始终是最新资料。

“重播画面”只影响观看状态，与咨询状态机的阶段回退分开。用户修改出生输入或核心事实后，相关下游报告应按现有失效机制处理，不能继续展示为当前有效结论。

### 内容异常时的表现

| 情况 | 产品应如何呈现 |
|---|---|
| 过去经历很少 | 用已知条件与未解问题形成简图，不补写人生阶段 |
| 时间不确定 | 保留顺序或明确时间未定位，不强行画年龄刻度 |
| 存在相反反馈 | 呈现两种理解或暂停相关连接，优先让用户看见分歧 |
| 没有合适行动 | 提供观察、维持现状或继续了解的入口 |
| 节点过多 | 首屏聚合为阶段，逐段展开，详情保持可访问 |
| 动画不可用 | 静态图和短文字仍能完整说明当前状态 |
| 绘图生成失败 | 保留两份已完成报告，提供可阅读的降级页面与重试入口 |

## 八 接入现有产品的工程方案

当前已按 [HTML 协议](../afei-destiny-skill/references/html-report.md) 接入本地生成与校验。下文区分现有本地链路与仍待建设的在线交付；匿名演示文件仍不是正式生成器。

### 生成链路

```text
当前会话的活动来源
    ↓ 现有审计与报告写作
final_report.md 与 technical_analysis.md
    ↓ 用户报告校验与两份报告登记
结构化可视数据
    ↓ 来源校验  内容一致性校验  布局检查
此后 HTML 与独立分享产物
    ↓ 用户导出观察记录并带回原咨询
新增现实反馈 → 更新分析与报告 → 生成下一版本
```

现有输出路由明确拒绝 `html_report`；正式接入需要增加来源选择、生成、验证、登记与失效支持，不能只复制一份模板到会话目录。[当前路由边界](../afei-destiny-skill/references/output-routing.md)

现有结构化中间数据为会话内 `visual_report_model.json`，完整字段以 HTML 协议为准。它描述本次主题、经历节点、关系、行动、条件分支、详细图解、来源与版本。生成器只消费同一会话的活动报告与来源，前端依据这份数据绘图，不在播放时另行推理或补写命运。

### 最小数据契约

| 数据 | 必需信息 | 用途 |
|---|---|---|
| 报告身份 | 会话、报告版本、生成时间、来源快照 | 避免跨会话与新旧产物混用 |
| 节点 | 稳定编号、简短名称、类别、正文、来源 | 支持主图、详情、修正同步 |
| 关系 | 两端节点、关系解释、依据、成立条件、反例或未知项 | 防止把节点相邻直接当成因果 |
| 行动 | 用户可做的具体事情、成本、所需条件、可观察变化 | 使预演落在现实可讨论的范围 |
| 分支 | 触发条件、依赖谁、下一项观察、待确认部分 | 保持情景而非保证结局 |
| 图文解读 | 对应报告章节、主题与反馈状态 | 保留完整内容与来源 |
| 观察记录 | 来自哪个版本、用户想尝试或实际尝试了什么 | 区分页面点击与现实行动 |

来源类型、是否发生、用户反馈与解释状态应分别存储，不能合成一个“可信度分数”。布局位置、颜色和动画速度不进入分析数据。

正式验证至少覆盖：节点和来源可解析、没有过期来源、分支有条件、正文与图一致、无法从分享文件恢复私人资料、极少与极多节点可读、手机操作、减少动画、重置和回访版本一致性。用户文本按安全文本渲染，不能作为脚本或任意 HTML 执行。

### 手机交付与长期服务的分界

正式首期面向“现有 Skill 用户生成、桌面及手机阅读”。本地 `127.0.0.1` 预览只服务于当前电脑，响应式测试也不等于手机已经能拿到报告。手机交付应有一条明确路径：

```text
Skill 完成报告 → 用户授权创建私人阅读副本
→ 返回受访问控制的 HTTPS 链接
→ 用户在手机验证访问权限 → 阅读与试演
```

建议把最小的私有在线阅读器纳入正式交付阶段：只负责读取报告，先具备访问验证、撤销与删除、版本标识；不同时建设网页内咨询与复杂账户中心。完整报告不能仅靠一个可转发的公开长链接保护。选定托管与身份方案后再估算工程成本。

用户也可以保留本地 HTML、两份 Markdown 和独立分享图。HTML 文件在目标手机上的传输、打开和交互需另外验收；不能把附件预览当作已经验证的浏览器体验。首期反馈仍通过导出记录回到原对话，跨设备草稿同步暂不承诺。

发布前至少走通一条真实 iPhone 和一条真实 Android 阅读路径，并检查分享链接不会扩大私人报告访问权。如果访问控制尚未准备好，就只发布本地试用版，清楚说明其范围。

## 九 分阶段落地与验收

### 第一阶段 完整体验原型

以当前演示为起点，制作至少三个内容和结构明显不同的匿名案例，覆盖反馈环、接桥、汇流，并补充信息不足的简图状态。打通来处、此刻、此后，加入图文解读、依据与纠正入口、观察卡的示例。

这一阶段优先验证完整体验、视觉语言与内容差异。样例中的修改与回访必须标为模拟，不能伪装成已经接入咨询状态。

### 第二阶段 正式咨询交付

本地部分已实现：个人结构化模型、校验器、生成器、Harness 和路由的登记与失效支持。默认交付个人 HTML，双 Markdown 留作内部底稿与可选下载；不再将两份长报告作为默认入口。其余待办包括：加入独立分享图片与明确的观察记录导出，让用户能够在原对话中继续。同步建设最小私有在线阅读器，打通从电脑生成到手机访问的路径；在线发布与本地导出都保留明确的隐私范围。

过关条件是：来源清楚、各模式可用、信息少时不会编造、反馈修正能生成相应新图、报告与分享数据隔离、不同设备能读。必要时允许退回简图或文字报告。

### 第三阶段 连续回访与独立阅读器

在前两阶段验证价值后，再建设私有报告集合、版本对照、浏览器内反馈和跨设备记录同步。是否需要独立完整咨询应用，由实际的入口与使用障碍决定。提醒只在用户主动选择后启用，不按“预测的坏日子”制造回访压力。

### 首轮用户验证

建议邀请 8 至 12 位首次接触者，在手机上试用不同匿名案例。以下是待验证的设计目标，不是当前已取得的数据：

| 验证问题 | 方法与目标 |
|---|---|
| 第一眼是否抓住重点 | 看 10 秒后，至少八成参与者能说出当前主要问题或关系 |
| 操作是否直接 | 不讲解按钮，至少八成参与者能完成一次行动预演 |
| 是否看懂条件变化 | 操作后能说明行动改变了哪个条件，而非只说球去了另一边 |
| 是否误读为保证 | 若出现把分支当预测、把点击当现实行动的误解，记录原因并修改设计 |
| 是否真的个性化 | 比较案例时，用户能指出经历、结构和选择的差异 |
| 是否允许反驳 | 用户能找到不符合自己的部分，并理解怎样纠正 |
| 是否值得带走 | 用户能保留一个有意义的理解、观察问题或自愿尝试的行动 |
| 是否易于手机阅读 | 真机能接收并打开私有报告；无横向溢出、关键触点易点中、静态状态不丢含义 |

小样本用于发现设计问题，不用于宣称统计意义上的有效率。分享意愿与惊艳感单独访谈；停留更久不一定意味着更有价值，用户纠正了原有解释也可以是成功。
