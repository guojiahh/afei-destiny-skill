## 为什么同一套 HTML 可以因人而异

共享的是品牌、阅读层次、绘图方法、来源入口和手机布局。每次重新编排的是主问题、节点、关系、来源、讲解、行动与外部条件，以及下方图文。模型由咨询代理基于本次活动双底稿生成，渲染器校验并绘图；当前不是脚本自行推断个人因果。

先材料，再关系，再选图：循环需回连依据；接续或开链保留真实缺口；汇流要区分已具备与尚待承诺的资源；信息不足保持留白。完成线／门槛适合讨论何时允许下一步发生。不能让每个人套用林舟，也不能用不同颜色冒充个性化。

当前正式渲染器支持有来源的节点和边、有限自动讲解、图内接管、完成线专属开门动效和通用关系图。其他类型尚未全部达到第一阶段循环图的空间细节。重点节点范围为 2–12 个，更多信息进入详报；不是无限节点自动布局，也不是所有图型都已精修。

## 新对话必须完成的链路

1. 按 Skill 先 `discover`，用户选择后新建或继续单一会话。继续时 `status`、`audit`、`resume`，不借用其他咨询或匿名案例材料。
2. 沿现有咨询完成资料、计算、锁定、反馈、深入与未来。由用户逐轮提供反馈，不编造其回答。
3. `report_ready` 后准备、校验并登记用户与技术两份底稿。它们保留来源隔离，承担完整内容与核对作用。
4. 按 [HTML 协议](../afei-destiny-skill/references/html-report.md) 获取章节来源索引，编排本次 `visual_report_model.json`。节点、关系和卡片均带引用，完整用户章节恰好覆盖一次，全部技术章节在同页可展开。
5. 生成并验收个人页面，再 `--register`、`--check`、Harness `audit`。默认 HTML 会话缺少有效页面时保持未完成；不能只交两份长文就结束。
6. 最终只突出 HTML 一个入口并打开它。完整解读在页面中，技术依据和底稿下载按需使用。

用户明确只要 Markdown 时，可以记录 `delivery_format=markdown`。历史无该字段的会话保留旧交付语义，不自动批量迁移；用户指定补 HTML 时才对该会话使用 `set-delivery`。更新底稿或模型先 `supersede`，新页面使用新文件名；旧页面的血缘失效，但已下载的离线副本不会远程消失。
