# 八字知识与推理缺口审计

审计日期：2026-08-11

## 结论先行

当前 Skill 的首要问题不是“完全没有八字知识”，而是缺少一层稳定的裁决协议：旺衰、格局、调候、病药和用神语义容易混在一起；合冲被识别后，缺少从“关系成立”到“结构改变”再到“具体事件”的门槛；用户反馈也没有与首次盘面判断完全隔离。

本轮因此没有盲目扩充口诀，而是补齐三块核心能力：

1. **结构分析**：把强弱、格局组织、寒暖燥湿、病药通关分成四条轴，并明确不同“用神”含义。
2. **关系结果**：把合、冲、刑、害、破、三合、三会、墓库分成检测、参与、结构作用、事件映射四层。
3. **反馈校准**：先形成不可被经历污染的首次判断，再用标准标签记录命中、宽泛命中、失误和未知。

这次补全提高的是知识覆盖和推理可审计性。由于没有重新建立未揭晓保留集，不能据此声称预测准确率已经提高。

## 审计范围与方法

审计覆盖：

- 可安装 Skill 的入口、路由和全部参考资料；
- 确定性排盘器及 9 项回归测试；
- 2010–2025 比赛题评测的错因汇总与 `knowledge_gap` 个案；
- 公开古籍文本和若干开源命理项目的结构、许可证与验证方式。

每个候选缺口按四个问题审查：

1. 是缺计算事实、缺知识、缺推理，还是问题本身不可识别？
2. 同一问题是否跨至少 3 题、2 个案例复发？
3. 新规则能否写出适用条件、反例和冲突口径？
4. 新内容是否会把 benchmark 答案、用户经历或其他术数体系污染进八字主引擎？

## 现有能力基线

| 模块 | 审计前状态 | 主要证据 | 本轮结果 |
|---|---|---|---|
| 历法与四柱计算 | 较完整 | 计算器、明确口径、内置依赖、9 项测试 | 保持不变；不在缺证据时调整权重 |
| 旺衰与格局 | 有原则，缺系统裁决 | 原协议强调月令、根气、透干，但格局成败与从格门槛分散 | 新增四轴结构审计与特殊格局闸门 |
| 用神 | 术语易混 | 原资料同时出现扶抑、调候、格局用法 | 明确格局、扶抑、调候、病药四种语义 |
| 合冲刑害 | 能识别，结果判断偏粗 | 表格列出关系，部分固定强弱和转化描述过硬 | 新增四层关系模型与合化条件 |
| 大运流年 | 较完整 | 有时间矩阵、候选年份比较与换运日修复 | 接入结构和关系结果，不另造一套断法 |
| 领域映射 | 较完整 | 事业、财富、关系、健康等按题加载 | 保持领域映射，但禁止从单信号跳到具体经历 |

| 其他术数 | 有隔离原则，路由曾失误 | 紫微大限曾被八字大运替代 | 继续隔离，不伪造紫微知识模块 |

## 评测揭示的真实缺口

主线评测的 97 道错题中，55 道被标为低可识别或证据不足，30 道为推理错误，6 道为执行错误，3 道为知识缺口，2 道为计算错误，1 道为选项解析错误。详见 [`../evaluation/competition-iterations/iteration_report.md`](../evaluation/competition-iterations/iteration_report.md)。

尤其重要的是：3 道 `knowledge_gap` 全部具有同一个内核——题目要求紫微斗数的大限，回答却用八字大运和流年替代。它们不是“八字古法不够多”，而是系统边界和路由错误。正确修复是拒绝跨体系替代，或未来单独建立并验证紫微模块。

反复达到修改门槛的八字内核，主要是：

- 从宽泛结构越级推到具体人生结果，忽略阶段和现实基准率；
- 醒目的合冲压过整体功能链；
- 复合选项没有逐个检查必要子句；
- 候选年份没有使用同一尺度完整比较。

所以，继续堆积神煞、口诀和“一柱一断”不会优先解决主问题，反而会增加冲突和事后解释空间。

## 本轮补全

### 1. 结构分析协议

新增 [`../bazi-skill-main/references/structure-analysis.md`](../bazi-skill-main/references/structure-analysis.md)：

- 分开记录力量、组织、气候和病药四条轴；
- 普通格局先提出候选，再审月令、透藏、有情、成败与救应；
- 从格、专旺、化气必须经过严格闸门，有反向根气或制化时主动降级；
- 输出“用神”时必须注明是格局、扶抑、调候还是病药语义；
- 原局结论与岁运触发分开，避免流年一出现某字就重写全局。

### 2. 合冲、合化与墓库协议

新增 [`../bazi-skill-main/references/relations-and-transformations.md`](../bazi-skill-main/references/relations-and-transformations.md)：

- “看见一组关系”不等于“发生合化”，更不等于“必然发生某事件”；
- 天干五合、地支六合、三合、三会、半合和拱局都增加月令、透干、根气、冲破、竞争关系检查；
- 多组关系同时存在时，按全局功能、月令和实际承载裁决，不按口诀固定排名；
- 墓、库、开库、闭库登记为条件性解释，禁止见冲即断“开库发财”或“入墓有灾”。

同时修订 [`../bazi-skill-main/references/wuxing-tables.md`](../bazi-skill-main/references/wuxing-tables.md)：删除“半合力量减半”“三会必强于三合”等无条件表述；把隐藏干 `60/30/10` 明确为计算器可解释的启发式权重，而非古典定律。

### 3. 用户反馈证据协议

新增 [`../bazi-skill-main/references/evidence-feedback.md`](../bazi-skill-main/references/evidence-feedback.md)：

- 出生信息与现实经历分栏；经历只能用于校验，不能冒充排盘输入；
- 第一轮先锁定盘面事实、结构判断、反证和置信度；
- 反馈按命中、部分命中、宽泛命中、失误、未知、已知事实复述标注；
- 允许纠正排盘口径、时间边界和证据权重，不允许事后发明规则或偷偷改写原判断；
- 回溯问题最多追问少量真正能区分假设的问题，避免用密集套话制造“说中心里”的错觉。

### 4. 来源治理与路由

修订 [`../bazi-skill-main/references/classical-texts.md`](../bazi-skill-main/references/classical-texts.md) 和 [`../bazi-skill-main/SKILL.md`](../bazi-skill-main/SKILL.md)：

- 古籍、注解和现代归纳分层；
- 新规则必须登记来源、语境、条件、反例、冲突和验证方法；
- 按问题加载结构、关系和反馈协议；
- 非八字问题不得用八字大运、十神或合冲作为替代证据。

## 公开资料与开源项目对照

本轮以公开文本核对了[《三命通会》四库本](https://zh.wikisource.org/zh-hans/三命通會_(四庫全書本))、[《滴天髓》](https://zh.wikisource.org/wiki/滴天髓)、[《滴天髓阐微》](https://zh.wikisource.org/zh-hant/滴天髓闡微)、[《渊海子平》](https://zh.wikisource.org/wiki/淵海子平)、[《神峰通考》](https://zh.wikisource.org/wiki/神峰通考)与[《穷通宝鉴》](https://zh.wikisource.org/wiki/窮通寶鑑)。使用方式是归纳可核验的分析原则，不大段复制原文，也不把后世注解伪装成同一时代的统一结论。

开源项目只用于工程对照：

- [`6tail/lunar-python`](https://github.com/6tail/lunar-python)：本项目已内置其 1.4.8 代码，适合作为历法计算依赖，但命理解读仍需独立协议和测试。
- [`shunshi-ai/bazi-reader-mcp`](https://github.com/shunshi-ai/bazi-reader-mcp)：可借鉴确定性计算、真太阳时口径和跨实现一致性测试的思路。
- [`HeiGeAi/HeiGe-SuanMing`](https://github.com/HeiGeAi/HeiGe-SuanMing)：知识目录很广，但采用非商业许可证；本轮没有复制其提示词或知识正文。
- 高星仓库也可能只有很少提交和一份书单，不能用 star 数替代知识深度、来源质量和回归证据。

## 没有在本轮做的事

- **没有修改计算器权重。** 当前五行权重用于透明初筛；没有外部一致性样本时，改数字只会把一种经验换成另一种经验。
- **没有加入紫微、盲派或其他术数的伪模块。** 如果未来需要，必须独立定义输入、计算、来源和测试。
- **没有把用户体验文案写得更绝对。** 具体感来自证据分层和可区分的问题，不来自恐吓、套话或“杀有介事”的语气。
- **没有生成 HTML 报告。** 统一入口和报告是下一阶段产品层，应该建立在本轮知识与证据协议稳定之后。
- **没有宣称准确率提高。** 当前 515 题已暴露给迭代流程；需要一套新的、答案未揭晓的保留集才能检验净增益。

## 下一轮验证建议

1. 建立 30–50 个不含人物身份与答案线索的新案例，预先锁定问题、答案和评分方法。
2. 将错误拆为计算、结构、关系结果、领域映射、时间选择、表达越级和不可识别七类。
3. 对同一出生数据与另一个独立排盘实现做四柱、节气边界、起运时刻和真太阳时一致性测试。
4. 在不提供经历的首轮完成 `chart_lock`，第二轮再揭晓经历并按反馈标签评分。
5. 只有跨 3 题、2 个案例重复出现的同一内核，才继续写入通用规则。

完成这些验证后，才能分别回答两个问题：计算是否更一致，咨询判断是否真正更准。
