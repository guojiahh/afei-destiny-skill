# 此后第一阶段 · 已完成的体验基线

2026-10-16。**第一阶段已完成并获用户确认。** 本文记录今后开发需要保留的表达、视觉与阅读约束；生成流程和字段以 [HTML 协议](../afei-destiny-skill/references/html-report.md)为准。用户已将方案统一为：所有新完整报告都使用莫比乌斯环，不再按咨询选择其他图型。

## 1 产品重心

一张主图聚焦一个主要矛盾：过去的考虑、现在的处境、可能的持续机制、能够介入的位置和仍待观察的后续。其他领域放在正文，不把人生全景塞进首屏。

莫比乌斯环是统一视觉隐喻，不是对每个人心理原因的断言。外部条件主导或原因未知时，文字应直接说明。过去、关系与行动都必须来自本次报告；反例改变解释，模板不强迫保留已经被推翻的关系。

## 2 固定阅读层次

| 层次 | 任务 | 阅读方式 |
|---|---|---|
| 主图 | 抓住本次矛盾，看见一种改变 | 图内三态，不弹窗、不跳页 |
| 主问题详解 | 来处、机制、具体场景、介入和取舍、未来 | 连续叙述、路径与时间带 |
| 其他方面 | 完整咨询的八领域与未知 | 手机单列，按实际深度展开 |
| 依据与原件 | 计算、规则、原判断、反馈和完整原文 | 文末单层展开与离线下载 |

HTML 正文固定九章：主问题、持续机制、现实场景、有限尝试、路径取舍、未来窗口、其他领域、反馈修正、边界收束。标题与内容随人变化，顺序和职责不变。完整章节 ID、布局与底稿模板只在 HTML 协议维护。

## 3 首屏的内容预算

首屏保留小品牌、两行个人标题、一张主图、一句解释、一处图内操作提示，以及低调的暂停和重看。不要加入目录、来源编号、技术参数、全景小卡片、成片说明和多层英文装饰。

标题先说清本次问题。解释整句替换，使用同一位置；旧字先淡出，画面动作后新句出现，不逐字飞入、不随人移动、不自动轮播。字数应在桌面和 320／390px 窄屏中实看，模型单行上限不是排版推荐目标。

## 4 同一个环的三种状态

| 状态 | 画面 | 本次内容应说明什么 |
|---|---|---|
| 路上 | 局部道路，低速循环的浅色刻痕 | 原有做法或处境为什么曾显得合理 |
| 全环 | 深色纸带完整出现，朱红人物持续行走 | 哪些因素可能使处境反复；或哪些原因仍待核对 |
| 跨出 | 人物先沿带面到前景，再走向环外空白；旧环保留 | 一次可选择的行动、观察、求助或暂缓，以及尚待外部回应的条件 |

由用户点击改变状态；观看时持续行走。人物离环不等于困境已消失、已获反馈或已经成功。可以保留认真、知识与积累，不用销毁旧环来象征改变。不要从高处坠落，不用光束、成功徽章或整图换景包装破局。

整张图是大触控区域，无须点准小人。点击只改变观看状态，不登记现实行动。重看从第一态开始；用户可随时向下阅读，不必播放完毕。

## 5 视觉基线

- 页面底色 `#f4f2ed`；正文深墨 `#252525`；次级文字 `#64635e`；人物与行动提示 `#be452f`。
- 生成图只有透明主体，背景由 HTML 提供。取消天空、夕阳、风景和装饰性纹理。
- 中文标题用宋体／明体，正文与控件用清晰黑体。正文以 16px 左右为基准，保持正常行距。
- 桌面左标题右图，手机为标题、主图、短解释纵向排列。主图与正文共享页面底色与留白。
- 实际实现以 [quiet 样式](../afei-destiny-skill/assets/cihou/quiet/report.css)及[交互脚本](../afei-destiny-skill/assets/cihou/quiet/report.js)为准。

[匿名样机](../design-demos/cihou-quiet.html)是视觉对照，正式开发从 Skill 内渲染器与资产继续。素材提示词和设计过程见[设计记录](../design-demos/cihou-quiet/README.md)。墨蓝机关、暮色景观和多人物图型均为历史，不能混入现役风格。

## 6 正文组织

重要结论、条件、反例和取舍默认可见；依据展开只负责核对，不承担藏起真正答案的功能。正文使用叙述、过程路径、主题、时间带、反馈与边界六类排版，避免每段都是同样卡片。

主文不放逐卡来源编号或跳转。可用短眉题说明依据状态，用简短列表展示步骤，让反例紧邻结论。完整用户八节和技术十一节原文集中在最后，两份 Markdown 原样内嵌下载。

过去只能讲已有材料支持的经历；条件式场景须说清只是核对工具。没有资料的领域简要说明未展开，不补齐常见人生故事。未来现实实验与传统窗口分开，不把某个年份变成录用或成功期限。

## 7 已实现的工程与移动端行为

当前采用两张透明 PNG、SVG 人物路径、原生 JS 与短淡化。页面全部运行资源内嵌，单文件离线可打开；不依赖在线 CDN、视频模型或 Three.js。图的几何共享，个人内容来自三态与正文模型。

这不是同一 3D 场景的连续运镜，也没有验证精确单面拓扑。二维路径的目的在于清楚地表现持续和介入。未来若升级实时 3D 或视频，必须沿用文字时机、留白与阅读结构，并先证明改善理解。

保留正常滚动、不强制横屏、不依赖悬停或拖拽；按钮触控区域至少 44px。窄屏主题与时间带变为纵向，长表格只在容器内横滑。支持键盘 Enter／Space、暂停、重看、离屏／后台停止、减少动态静态状态和无脚本正文。

## 8 第一阶段完成凭据与保留边界

完成范围：用户认可当前静纸视觉与交互，已结合指定的完整咨询生成、检查并登记个人 HTML；默认交付、双底稿、个人模型、来源登记、失效与完成判定形成闭环。本次收尾进一步固定所有新报告的主图与正文模板。

验证包括合成来源测试、完整章节和下载一致性、桌面及 320／390px 浏览器视口、图内点击、暂停与重看、窄屏表格。真实资料与验收截图留在私有会话，公开样机只含匿名虚构内容。

仍未完成：独立首次读者理解测试、实体手机接收与浏览器打开、在线私有交付。第一阶段按用户验收完成，不以此声称已验证普遍理解率或真机性能。

## 9 第二阶段开发原则

本轮仅完成收尾，不直接启动新功能。后续范围以[产品方案](CIHOU_PRODUCT_PLAN.md)和[交接说明](CIHOU_HANDOFF.md)为准：优先真实手机交付与访问控制，再讨论回访、版本与脱敏分享。保留现役图形母题，不重开多图型库，也不为装饰增加首屏文字或入口。

### 动效工具依据

Three.js 使用 [MIT 许可](https://github.com/mrdoob/three.js/blob/dev/LICENSE)。其官方[响应式指南](https://threejs.org/manual/pages/responsive.html)指出高像素密度会增加绘制负担；[按需渲染指南](https://threejs.org/manual/pages/rendering-on-demand.html)说明静止画面持续绘制的能耗问题。这些分别对应手机像素预算和离屏暂停。

GSAP 的[官方价格说明](https://gsap.com/pricing/)支持当前免费商用，但须遵守 [Standard No Charge License](https://gsap.com/standard-license)，不能称为 MIT 或无限制开源。若采用，在本地打包时固定版本并保留许可；依据[官方 matchMedia 文档](https://gsap.com/docs/v3/GSAP/gsap.matchMedia%28%29/)处理屏幕与减少动画条件。
