# 此后第一阶段体验重构方案

2026-10-16。方案阶段；本轮形成内容结构、主图分镜、视觉方向与验收标准，尚未替换正式 HTML。

第一阶段的目标是：**一张主图讲透一个主要矛盾，点一下看懂自己的行动改变了哪里，向下顺着读完整次咨询。** 已接通 HTML 生成和来源登记，不等于体验已经过关。本轮优先解决主图表达和阅读组织，保留已经完成的交付工程。

## 1 产品重心

「此后」围绕本次最重要的问题，帮助用户看见过去怎样接到现在、什么使一种处境持续、当下有哪些可以介入的地方，以及不同条件下的后续可能。它不需要在首屏画完一个人的全部人生。

画面应表达具体机制。例如循环必须让人看见“走了一段，又回到了哪里”；行动必须改变某个连接、次序或获得信息的方式；未来必须留出环境与他人回应的位置。单纯增加立体节点、流动光点、阴影或金色出口，都不能替代这些含义。

哲学表达落到体验里：过去形成了当前的一部分条件，而当下的思考、选择和尝试也会成为后续条件。用户介入的是同一个结构中的一处关系，旧经历和现实限制依然存在。画面不以万能外力抹掉过去，也不以点击直接产生理想结局。

## 2 页面只保留四层

| 层次 | 读者得到什么 | 阅读方式 |
|---|---|---|
| 主图 | 主要矛盾、当前位置、可介入之处 | 看一次短动效，直接点图 |
| 主问题详解 | 形成过程、持续机制、现实缺口、行动与条件未来 | 连续图文，默认可见 |
| 其他方面 | 本次咨询对其他生活领域的分析 | 顺读，有材料的展开讲，未深入的简述 |
| 依据与原件 | 计算口径、传统解释、反馈修正、来源文件 | 分组原地展开，原文件按需下载 |

这四层是阅读顺序，不是四个必点入口。首屏无模块菜单；主问题讲完后才进入其他方面。未来、行动、反例都归属于主问题内部，避免在整份报告中来回寻找。

### 主问题详解的内部顺序

1. **这条路怎样形成。** 少量有来源的经历或决策片段，解释当时的考虑、短期作用与后来代价。只有近期材料就解释近期模式，不补写童年、创伤或固定人格。
2. **为什么总回到这里。** 将首屏器物展开成一幅短关系图，解释关键回连。一条推断需要说清支持和可推翻它的条件。
3. **现在卡在哪一处。** 区分已经在做什么、缺少什么外部信息、有哪些未核实的现实约束。不能把仍有行动的人写成完全没有行动。
4. **从哪里试着改变。** 只突出一个介入点，写清一次可尝试的行动、必要条件和下一项观察。避免将行动清单包装成另一套必须全部准备好的门槛。
5. **此后可能怎样。** 用两个相邻场景比较延续原方式和引入新条件的差别；先展示信息、选择或协调方式发生什么变化。没有回应、不适用和现实限制也有位置。

与主问题有关的命理解释放在相应段落，以白话说明传统体系提供的观察角度、与现实反馈的对应及不适用处。技术计算留在附录。两种解释可以相互参照，命盘不能补写个人经历，也不能证明人格形成的科学因果。

### 其他方面的组织

八个主题仍检查覆盖，但不强制出现八张同样大小、同样饱满的卡片。主问题已经讲过的领域只承接一句；其他有实质分析的领域保留短图文；没有深入的领域合并为轻量说明，明确本次了解范围。未展开的个性信息不以模板补齐。

完整不以重复原文衡量。所有实质结论、关键限定、反例、未来解释和反馈修正都有归属；同一个核心观点只完整解释一次。原始双报告保留在最后，承担核对和下载用途。

## 3 首屏的内容预算

首屏采用一件具有鲜明轮廓的立体器物。图形占主要面积，标题和短句建立含义，细节随点击出现。

| 元素 | 本轮设计约束 |
|---|---|
| 品牌 | 小型「此后」，不附多层英文装饰和标语 |
| 个人标题 | 最多两行，约 12–20 个汉字；直指本次矛盾 |
| 主体 | 只有一个；桌面和手机分别构图 |
| 常驻短标签 | 不超过 3 处，每处约 2–6 字；不伴随小字解释 |
| 当前短句 | 固定一处，约 18–32 字；同一时刻只讲一件事 |
| 操作 | 图内大范围触控；低调的暂停或重播控制 |
| 下读提示 | 一处普通向下阅读提示 |

这些是样机的初始预算，需以实际理解测试调整。首屏不出现来源编号、分类图例、技术参数、阅读目录、成片说明和完整报告的入口按钮。

彻底去掉文字也会失去个人含义。因此保留一个能说清问题的标题和随动作变化的一句解释，让器物不只是漂亮的摆件。

## 4 循环主图的设计

循环型优先制作，采用莫比乌斯带的扭转与前后遮挡作为形态灵感。它是关系的视觉隐喻，工程上用可以转向的带面结构表达介入。

### 一个主体承载五种含义

| 想表达的内容 | 画面承担的工作 |
|---|---|
| 过去 | 同一带面上留下回行痕迹，进入相关区域时短句承接已知经历；不伪造次数或年代 |
| 现在 | 唯一明确的当前位置，光线在那里停留 |
| 为什么持续 | 运动沿带面经过遮挡，最终回到可辨认的起点；回连必须清楚 |
| 如何介入 | 带面的一处暖铜色转向面，可直接点中 |
| 条件未来 | 转向后伸出外部检验路径；回应端保持开放，反馈可以返回并改变下一步 |

人不需要认出“莫比乌斯环”这个名词，也应该看懂反复与转向。不要把“环”设计成所有人的默认命运：外部约束造成的困境、资源汇聚、信息缺口仍需要别的关系形状。

### 分镜与点击

| 时段或操作 | 图形变化 | 解释目标 |
|---|---|---|
| 打开 0–2 秒 | 直接出现完整轮廓，来路亮起，无长加载仪式 | 先认出一个主体 |
| 2–6 秒 | 线索沿带面回到原处，跨过前后遮挡 | 看懂什么在重复 |
| 6–9 秒 | 停在当前位置，转向面有一次轻微提示 | 知道我在哪里、哪里可以尝试 |
| 点过去区域 | 同一器物上显出相关路径，替换一句短解释 | 看懂当前方式的来处 |
| 点回环区域 | 再走一次关键回连，其他部位降低干扰 | 看懂为什么持续 |
| 点转向面 | 局部带面在约 2–3 秒内转向，线索进入外部路径 | 看懂行动改变的是关系与顺序 |
| 转向完成 | 停在外部检验接口；当前短句说明仍待现实回应 | 看懂未来是条件性的 |

自动讲解一次后停止；手动点击随时接管。首屏不需先点一个图外的“预演”按钮。点击不滚动页面、不弹面板，不自动跳到报告某一节。桌面鼠标只能提供轻微辅助，全部必要操作在手机点按即可完成。

如果需要展示收到反馈的情景，明确进入“反馈情景”的第二次点选，不能由首次点击自动替外部世界给出答复。第一阶段点击只改变临时观看状态，不登记现实行动；真实反馈仍回到原咨询处理。

### 突破应当保留什么

旧环在转向后仍可辨认，原有认真、知识或积累不被销毁。新路体现的是把实践和外部反馈接进来，让下一轮投入有更具体的对象。不能通过整图换场、环消失、光束冲天或出现成功徽章来表示破局。

## 5 视觉方向

推荐继续使用暖白底，增加一个有雕塑感的墨蓝主体，以很少的暖铜色标出介入处。视觉集中在带面的连续曲率、清晰切面、遮挡、柔和接触阴影与转向瞬间。减少通用卡片、装饰细线和遍布全页的小字。

中文标题用有力度的宋体或明体，正文使用清楚的黑体；不照搬英文作品中的极小等宽字。正文目标字号 16–18 像素，文字按正常行距阅读，滚动时不拆成逐字飞入动画。艺术性主要留在主图，正文依靠清楚的段落与对照图。

![循环主图材质与构图概念](../design-demos/cihou-phase1-direction/loop-concept.png)

这张图由内置图像生成工具制作，只验证形态、光影和材质。正式首页只保留一件主体，右侧两个小图属于概念板分镜。下一轮应减弱首饰和金属扣的联想，把转向做成带面自身的一部分；反馈路径还需用交互样机验证。生成提示词和素材边界见[概念素材说明](../design-demos/cihou-phase1-direction/README.md)。

## 6 正文的阅读规则

正文采用连续的编辑排版：一个明确的小标题、一幅回答该问题的小图、一至两段具体解释，需要时补反例。核心内容直接可读，不让用户展开原文后才真正得到答案。

- 删除各卡片下的“解读 2”“依据 7”等编号锚点。内部来源映射继续存在，用户界面不暴露数据库索引。
- 一段正文只解决一个问题；关系对照、阶段带和取舍图按内容使用，不把所有段落统一切成相同卡片。
- 主问题结束处最多一项“查看这段理解的依据”，在原位展开短来源说明。其他方面按整节提供补充，不为每句话新增入口。
- 完整技术材料集中在文末，采用四组单层折叠：计算与口径、传统规则与推导、现实反馈与修正、原文件。
- 重要反例和限制仍紧邻相关结论，文末保留完整核对材料。不能把影响结论的内容全部藏到附录。
- 不进行跨章节自动滚动。以后如确需跳转，应有明确目标名称与返回阅读位置；第一阶段先移除这种需求。

来源文件保留原貌，面向读者的 HTML 重新编排其含义。下一版内容模型需要增加论点归属、限定与反例的覆盖映射，不能只用“每个 Markdown 二级标题出现过一次”验证完整性。

## 7 手机与工程取舍

主图建议用一个轻量实时 3D 场景，正文保持普通 HTML。首先验证简单网格的回环、遮挡和转向是否可读，再增加材质。图像生成用于艺术方向和静态降级封面，不以几张图片切换冒充可交互空间。

手机为纵向重新构图：完整回环、介入处和当前短句在常见首屏内可辨认，桌面可横向展开。热点按区域设置，触控范围至少 44×44 像素，不要求准确点中一条细线或悬停。不强制横屏，不用拖拽或缩放作为主要操作。

拟采用 Three.js 绘制主体，GSAP 统一管理形变、路径和字幕时间线；若少量状态用原生动画即可稳定实现，则不额外增加动画库。仅加载本次图型，运行资源随本地 HTML 打包，不依赖在线 CDN。

保留正常页面滚动；不做全站 WebGL、不劫持滚轮或手势。离屏和后台停止渲染，控制移动端像素比与材质成本。减少动画时直接呈现静态关系和相同文字，点击仍可切换状态；WebGL 不可用时用静态图配 HTML 语义摘要。

性能目标需要在样机上测：首屏文字与静态图先出现，3D 就绪后无突兀替换；连续触控不中断；普通手机动画优先保持稳定。不能用桌面截图代替真机性能和理解测试。

## 8 第一阶段的执行顺序

| 步骤 | 产物 | 进入下一步的条件 |
|---|---|---|
| 内容导演稿 | 一句矛盾、关键回连、当前位置、介入关系、反例 | 能说明每一条关系来自哪里 |
| 静态构图 | 桌面与手机各一版完整首屏 | 不依靠长文也能看出重点，字数预算成立 |
| 动态粗模 | 同一主体的原状、转向、待回应三个状态 | 点击后能看懂关系变化，不只是画面变形 |
| 视觉精修 | 曲面、材质、光线、节奏和字体 | 不增加阅读负担，达成主图吸引力 |
| 长文样机 | 主问题、其他方面、依据三段连续内容 | 无必需跳转，无重复堆叠，内容完整 |
| 个人适配 | 同型第二例、外部约束反例、少信息例 | 同型不同内容；反例足以导致换型 |

已有来源和登记流程继续使用。只有解释、图形和正文都一致，才生成个人报告的新版本；已登记的旧文件保持不变。本轮不扩展账号、托管、分享传播、回访系统或完整图型库。

## 9 体验验收

以下是设计目标，尚未取得测试结果。先用 5–8 位未参与设计的人做探索测试，关注误读，不以小样本宣称普遍有效。

1. 看 10 秒主图，能说明本次主要矛盾、当前在哪里、什么在重复。
2. 不提示固定按钮，能点到图内介入处；点击后能说出改变的条件。
3. 不把演示理解为已经采取行动、已经收到回应或必然成功。
4. 不点击任何依据，向下读仍能回答过去、现在、为何持续、怎样尝试、此后条件五个问题。
5. 能找到其他方面分析和计算依据，且不用经过多个互相跳转的入口。
6. 静态截图和减少动画状态仍可读懂主要关系；图形吸引力另行询问，不能以停留时间代替理解。
7. 320／390 像素布局无页面横向溢出；至少一台 iPhone 和一台 Android 验证点击、性能与长文阅读。
8. 如果新证据表明问题主要来自外部条件，主图会撤去不成立的心理回连。

第一阶段完成的标志是读者理解成立、视觉吸引力成立、阅读路径成立。生成器成功运行只证明交付工程可用。

### 动效工具依据

Three.js 使用 [MIT 许可](https://github.com/mrdoob/three.js/blob/dev/LICENSE)。其官方[响应式指南](https://threejs.org/manual/pages/responsive.html)指出高像素密度会增加绘制负担；[按需渲染指南](https://threejs.org/manual/pages/rendering-on-demand.html)说明静止画面持续绘制的能耗问题。这些分别对应手机像素预算和离屏暂停。

GSAP 的[官方价格说明](https://gsap.com/pricing/)支持当前免费商用，但须遵守 [Standard No Charge License](https://gsap.com/standard-license)，不能称为 MIT 或无限制开源。若采用，在本地打包时固定版本并保留许可；依据[官方 matchMedia 文档](https://gsap.com/docs/v3/GSAP/gsap.matchMedia%28%29/)处理屏幕与减少动画条件。
